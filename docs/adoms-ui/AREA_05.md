# AREA 05 — 의무이행(실적증빙) 공중이용시설·교통수단 분석

**대상 범위:** SCR-052 ~ SCR-066 (화면 컷 15개, 실제 라우트 9개)
**작성:** Manus AI
**판독 기준:** 입력 명세, 화면 인덱스, 원본 PNG 15장을 각각 대조하였다. 본문에서 말하는 “화면”은 인덱스의 `SCR-0NN` 컷이고, “라우트”는 세로 스크롤·모달·비활성 상태를 합친 실제 페이지이다. [1] [2] [3]

> **범위 주의:** SCR-052~056은 파일 범위에는 포함되지만 좌측 대상이 `사업장`인 **중대산업재해 트랙의 마지막 구간**이다. SCR-057~066이 `공중이용시설 ·교통수단`을 선택한 **중대시민재해 트랙**이다. 따라서 이 보고서는 요청된 15개 SCR을 모두 다루되, 용인시 공중이용시설 시연 적용 판단에서는 두 트랙을 구분한다.

## 1. 결론과 화면 구조

이 영역은 15장의 화면 설계 컷이지만 실제로는 **9개 라우트**다. `SCR-053→054`는 하나의 “해당없음” 토글 상태이고, `SCR-055→056`, `SCR-057→058`, `SCR-063→064→065`는 동일 페이지의 세로 스크롤 구간 또는 모달 상태이다. `SCR-061→062`는 동일 안전계획 입력 페이지와 그 위에 열린 불러오기 모달의 관계다. 이 관계를 무시하여 컷 수만큼 라우트를 만들면 입력값, 스크롤 위치, 첨부 미리보기 및 모달 선택 상태가 분절된다.

공중이용시설·교통수단의 주 흐름은 `1) 안전인력 확보` → `2) 안전예산 편성·집행` → `3) 안전점검 계획 수립·수행` → `4) 안전계획 수립·이행` → `5) 재해예방업무처리절차` → `② 재해발생시 재발방지 대책 수립 및 이행` → (범위 밖의 개선·시정 및 관계법령 단계)이다. 모두 `공중이용시설 ·교통수단` 및 담당 시설의 문맥에서 저장되어야 하며, SCR-057~060만 우상단 `대상` 값 `제방1`이 보인다.

## 2. SCR별 상세 명세

### 2.1 SCR-052 — 사업장 재발방지대책의 하단 뷰어

| 구분 | 분석 결과 |
|---|---|
| 번호·정확한 화면명 | **SCR-052** — `의무이행(실적증빙) – [사업장, 부서] 재해발생시 재발방지대책 수립 및 이행 (계속)` |
| 역할·진입조건 | `사업장` 선택, `② 재해발생시 재발방지 대책 수립 및 이행` 활성 상태에서 재발방지대책 입력표 아래로 스크롤한 연속 구간이다. 제목은 `재해 발생시 재발방지대책 수립 및 이행(중대재해법 시행령 제4조 제2호)`이다. 독립 진입 페이지가 아니다. |
| 사용자 액션 | 앞선 표에서 첨부 증빙을 선택하면 `이미지 뷰어`에 이미지 미리보기를 렌더한다(추정). `수시 위험성평가는 “유해·위험요인 확인 및 개선 절차 마련(위험성평가)”등록·관리 (바로가기 링크)`를 선택하면 위험성평가 등록·관리로 이동한다. |
| 저장/조회 데이터 | 이 컷 자체의 입력값은 없다. 선택한 `duty_evidence` 파일, 이미지 가능 형식의 프리뷰 URL/상태, 필수 내역과 정적 증빙 예시를 조회한다. `필수 내역`은 `1. 재해발생 상황보고서, 2. 산업재해조사표, 3. 재발방지계획서, 4. 수시 위험성평가`다. |
| 이전/다음 | 화면 표기는 이전 `< 7단계: 종사자 의견 청취 및 개선`, 다음 `10단계: 중앙행정기관, 지자체 개선·시정 사항 이행 >`다. 8·9단계를 건너뛰므로 실제 표기대로 보이되 연결 규칙은 확인이 필요하다. |
| 같은 화면 상태 관계 | 사업장 재발방지대책 라우트의 **스크롤 하단**이다. 비어 있는 뷰어는 첨부 파일을 선택하지 않은 상태다. |

### 2.2 SCR-053 — 개선·시정 사항 이행의 기본 입력 상태

| 구분 | 분석 결과 |
|---|---|
| 번호·정확한 화면명 | **SCR-053** — `의무이행(실적증빙) – [사업장, 부서] 중앙행정기관, 지자체 개선·시정 사항 이행` |
| 역할·진입조건 | 사업장 트랙의 `③ 개선·시정 등을 명한 사항 이행`을 선택하여 중앙행정기관 또는 지자체의 개선·시정 요구와 조치 실적을 등록하는 기본 편집 상태다. |
| 사용자 액션 | `개선 시정사항 추가`는 빈 행을 추가한다. 행의 `+`는 증빙 파일 슬롯을 추가하고, 파일 `⤓`/`🗑`은 다운로드/삭제, 맨 우측 `🗑`은 행 삭제다. 상단 `⊘ 중앙행정기관, 지자체 개선·시정 사항이 없을 경우 체크하여 저장`을 체크하면 SCR-054 상태가 된다. `저장`은 테이블을 일괄 저장한다. |
| 저장/조회 데이터 | `개선·시정 사항`, `개선·시정 요구기관`, `행정처분 일자`, `개선·시정 사항 이행 내역`, 시작·종료 `조치기간`, 다중 증빙, `비고` 및 행 ID를 `target_id + duty_item_id + 연도` 범위에서 저장/조회한다. 예시는 `test`, `2023-08-04`, `보고서.png`이다. |
| 이전/다음 | 이 컷에는 단계 네비게이션이 보이지 않는다. 명세는 스크롤 하단에 있을 가능성을 추정할 뿐이므로, 이전/다음 버튼을 이 컷 근거로 확정하지 않는다. |
| 같은 화면 상태 관계 | SCR-054는 별도 페이지가 아니라 이 화면의 `noneApplicable` 토글 ON 상태다. 하단에는 `이미지 뷰어`와 `증빙자료 예시(필수항목)`이 계속된다. |

## 4. 공통 셸·재사용 컴포넌트와 데이터 경계

### 4.1 공통 셸

전 화면은 `TopBanner` → 검은 `Header/GNB` → 좌측 2단 `TwoLevelSidebar` + 우측 본문 → 푸터의 고정 골격이다. 상단에는 `경영목표`와 `통합된 안전보건관리체계 확립으로 중대산업재해 ZERO 달성`, 우측에는 `경영방침`과 `1. 안전문화 정착`이 놓인다. GNB의 현재 메뉴는 `의무이행(실적증빙)`이다. 사용자 영역은 `하천관리과` / `김안전`, `정보수정`, `로그아웃`이다. 공중이용시설 컷 일부는 경영방침 옆 `❙❙` 표시가 없으므로 캐러셀의 캡처 시점 차이인지 확인이 필요하다.

좌측 1단은 `의무사항(실적증빙)` 안의 `사업장`, `공중이용시설 ·교통수단`, `원료·제조물`이다. 공중이용시설 트랙에서는 `◉ 공중이용시설 ·교통수단`을 진녹색 굵게 표시하고, 2단은 `① 안전보건관리체계 구축 및 이행` 아래 다섯 항목을 연다. 현재 하위 항목은 연녹색 채움, 상위 ②·③·④는 큰 여백 아래 연녹색 pill, 활성 그룹은 진녹색 채움과 흰 글자다. 이 LNB의 넓은 수직 여백은 원본의 중요한 밀도 특성이다.

## 6. 용인시 영업 시연: 사용·숨김·상태 재사용 판단

용인시 시연은 102개 설계 컷을 복제하는 제품이 아니라, 정해진 7개 대표 라우트 `/`, `/targets`, `/laws`, `/obligations`, `/evidence`, `/inspection`, `/summary`에서 `대시보드 → 대상 → 법적 근거 → 의무 기한 → 증빙 → 점검 → 조치 → 요약`을 안정적으로 시연해야 한다. 따라서 이 영역의 고유 업무 세부 페이지를 추가하지 않고, 아래 내용을 기존 `/evidence`의 상태와 재사용 컴포넌트로 흡수하는 판단이 적절하다. [4]

| SCR/기능 | 용인시 판단 | 근거 및 구현 위치 |
|---|---|---|
| 052 사업장 재발방지 하단 | **숨김** | 공중이용시설 시연 범위가 아니며, 일반 증빙 프리뷰 상태만 `/evidence`에서 재사용한다. |
| 053/054 개선·시정 + 해당없음 | **상태 재사용** | `/evidence`에 `해당없음`과 증빙 행 disable 패턴을 재사용한다. 중앙행정기관 세부 8열 표와 사업장 라우트는 보이지 않는다. `NA`는 완료율 분모에서 제외한다. |
| 055/056 관계법령/법정교육 | **사용(축소) + 숨김(세부)** | `/laws`와 `/obligations`의 읽기 전용 법적 근거·원본 ID 추적에 사용한다. 2개 표, `명부선택`, `샘플다운`, 별도 사업장 단계는 영업 시연에서 숨긴다. |
| 057/058 안전인력·조직도 | **사용(상태 재사용)** | `/targets`의 시설 담당자·대상 문맥과 `/evidence`의 첨부 프리뷰를 재사용한다. `담당 대상 일괄적용`은 다대상 복제의 위험이 높고 시연 핵심 흐름이 아니므로 숨긴다. |
| 059 고정 예산 5종 | **숨김** | 예산 입력·집행은 현 7-라우트 시연의 핵심 증빙 루프 밖이다. 필요하면 evidence의 한 obligation note/evidence 예시로만 시드한다. |
| 060 이중 안전점검 | **상태 재사용** | `/inspection`의 읽기전용 증빙 확인, 상태 `이행완료`/`보완필요`/`미이행` 및 점검 메모로 흡수한다. 외부 시설물안전법 연계 표, 두 개 대상 선택자·세부 수치 열은 숨긴다. |
| 061/062 안전계획 + 불러오기 | **사용(핵심)** | `/obligations`의 승인된 법·의무 매핑을 `/evidence`로 선택하여 불러오는 흐름으로 재사용한다. UI는 `SearchPickerModal`을 간소화하고, 빈 검색 결과도 명확히 표시한다. |
| 063/064 위험요인·비상대피훈련 | **상태 재사용** | `/evidence`에서 action date, note, evidence로 수용하고 `/inspection`에서 점검·보완 루프를 시연한다. 각각의 긴 테이블·설계 annotation은 숨긴다. |
| 065 절차도 PDF/HWP 카드 | **사용(파일 상태만) + 숨김(전용 UI)** | private bucket의 파일 메타데이터·버전 이력을 evidence에 유지하고 PDF 프리뷰/다운로드 상태만 쓰며, 두 카드·HWP 라디오 업로드 UI는 숨긴다. 미구현 HWP 뷰어는 클릭 가능한 버튼으로 두지 않는다. |
| 066 재해 카드·해당없음 | **상태 재사용** | `/evidence`의 accident-related obligation에 카드형 보조 입력을 조건부로 쓰거나, 영업 시연 기본 데이터는 `해당없음`으로 둔다. 사고 이력 데이터가 없으면 완전한 카드 CRUD는 숨기고 `해당없음` 상태와 근거만 보인다. |

**시연 구현 원칙:** 법령과 의무 매핑은 읽기 전용으로 유지하고, 이행일·비고·증빙·제출 상태만 쓰기 가능하게 한다. 파일은 private bucket에 메타데이터와 버전 이력을 남긴다. 대시보드와 요약 O/△/X/-는 저장된 상태에서 계산하며 `NA`/`해당없음`은 완료율 분모에서 빼야 한다. 구현되지 않은 `담당 대상 일괄적용`, 외부 연계, 템플릿 다운로드, HWP 뷰어는 반드시 숨기거나 disabled + 사유 표기로 처리해야 하며, 클릭해도 반응 없는 제어를 남기면 안 된다. [4]
