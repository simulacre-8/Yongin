# AREA 03 — 관리대상 현황 · 법 의무사항 UI 분석

**분석 범위:** SCR-021~SCR-035
**분석 기준:** 입력 명세, `SCREENS.csv`, 시스템 개요 및 원본 PNG 15장을 대조하였다. 이 문서는 화면에 보이는 한글 UI 라벨을 원문 그대로 표기한다. 설계서의 `(추정)` 또는 이미지로 확정할 수 없는 동작은 **발주처 확인 필요**로 분리하였다.

> **결론.** 이 영역의 15개 화면 컷은 15개 라우트가 아니다. 관리 대상/기본정보 흐름은 `목록 → 하나의 긴 기본정보 폼(SCR-028~029)`, 도급·용역·위탁 흐름은 `목록 → 하나의 긴 계약 폼(SCR-031~033)`, 법 의무사항 흐름은 `시설물 목록(SCR-034) → 시설물별 이행 시기 편집(SCR-035)`로 구현해야 한다. 담당자·권한·법령 마스터·활동로그는 관리자 전용 보조 화면이다. [1] [2]

### 1.2 역할 및 데이터 경계

이 구간은 **중대재해 담당부서(관리자)**와 **사업장, 부서**의 경계가 뚜렷하다. SCR-021~026은 전 기관 데이터를 보는 관리자용 LNB이며, SCR-027~035는 로그인한 `하천관리과` / `김안전`이 배정받은 대상만 조회·입력하는 담당자용 LNB이다. 따라서 화면 숨김만으로는 충분하지 않고, 서버 조회도 조직·관리대상 매핑으로 제한해야 한다. [1] [2]

| 사용자 화면군 | SCR | 주 데이터 권한 | 구현 원칙 |
|---|---:|---|---|
| `중대재해 담당부서(관리자)` | 021~026 | 전 기관 사용자, 조직, 사업장, 관계 법령, 경영책임자 활동 | 권한 부여·매핑·마스터 변경을 허용하되, 삭제/초기화는 확인 및 감사로그를 남긴다. |
| `사업장, 부서` | 027~033 | 본인에게 지정된 사업장/부서와 도급·용역·위탁 건 | 소관/매핑 대상만 읽고 쓴다. 기준일자 이력과 첨부파일 버전을 보존한다. |
| `사업장, 부서` | 034~035 | 본인 소관 `공중이용시설·교통수단` 및 대상별 법 의무사항 | 관계 법령 기준정보는 읽기 중심으로 두고, 시설물별 `이행 시기`만 쓰도록 분리한다. |

## 5. 육안 복제 포인트

### 5.1 색, 밀도, 프레임

원본은 넓은 데스크톱 행정시스템 밀도이며, 둥글고 큰 소비자용 카드 UI가 아니다. 외곽은 검정 배경/검정 GNB가 강하고, 본문은 폭 약 1,180px의 흰 캔버스와 왼쪽 약 260px의 연녹색 LNB로 분할된다. `SCR-027`, `SCR-034`처럼 검색 영역이 본문 폭을 크게 점유하되, 입력 자체는 흰 박스와 가는 회색 테두리로 조밀하게 정렬된다. [1]

| 요소 | 육안 복제 사양 |
|---|---|
| 상단 띠 | 매우 옅은 녹색, 약 50px 높이. 좌·우 문구 모두 굵은 검정/진녹색, 중앙 세로 구분 아이콘. |

## 6. 용인시 영업 시연 적용 판단

용인시 시연은 102개 컷의 화면 복제가 아니라 **`dashboard → target → legal basis → obligation due date → evidence → inspection → correction → summary`**의 7개 대표 라우트를 유지해야 한다. 따라서 이 영역은 원본의 관리 기능을 그대로 늘리기보다, 라우트에 맞춰 **사용**, **숨김**, **동일 화면 상태 재사용**으로 정리한다. 법령 기준정보는 읽기 전용이고, 시연 업무기록·증빙·상태는 쓰기 가능해야 한다. [4]

| SCR | 판단 | 용인시 시연에서의 처리 |
|---|---|---|
| 021 | **숨김** | 관리자 권한 부여/`권한인계`는 영업 시연 핵심 루프 밖이다. 필요한 담당자·역할은 시드/role switcher로 고정하며 미구현 버튼을 노출하지 않는다. |
| 022 | **상태 재사용** | 별도 관리자 라우트로 만들지 않는다. `/targets`에서 선택한 담당자/조직별 범위를 보여 주는 비편집 요약 상태로만 재사용 가능하다. |
| 023 | **상태 재사용** | `/targets`의 선택 대상 상세/기본 속성 패널로 축소한다. 삭제와 전 기관 마스터 수정은 숨기고, 시연 데이터는 대상별 속성으로 유지한다. |
| 024 | **사용(축소)** | `/laws`의 중대산업재해 관계 법령 검색 UI/테이블에 사용한다. 승인된 축소 법령 데이터는 **읽기 전용**으로 하며 `신규`는 숨기거나 disabled 처리한다. |

### 7.2 공통 코드와 계산 규칙

`FACILITY_TYPE`은 SCR-025와 SCR-034에서 하나의 마스터여야 하며, 값은 `전체`, `건축물`, `상하수도`, `옹벽`, `하천`, `터널`, `교량`, `절토사면`, `기타`다. `EMPLOYMENT_TYPE`의 8개 값은 SCR-028 매트릭스와 SCR-029 `작성요령`에서 동일하다. `COMPLIANCE_STATUS`는 SCR-033의 `이행완료`, `보완필요`, `미이행`을 기본값으로 공유하고, 후속 이행점검 집계에 필요한 `해당없음`은 전역 코드로 두되 이 화면의 선택지에 무단 추가하지 않는다. `MGMT_STATUS`의 관측값 `제정`, `지정`, `선임`, `위촉`은 항목별 허용 값으로 설정한다. ## 9. 구현 우선순위

1. **공통 셸, 권한 스코프, 공통 코드**를 먼저 완성한다. 특히 `TARGET_TYPE`, `FACILITY_TYPE`, `COMPLIANCE_STATUS`, `EMPLOYMENT_TYPE`을 화면 문자열과 분리되지 않게 단일 마스터로 둔다.
2. 담당자 시연 핵심인 SCR-027, SCR-034, SCR-035와 SCR-033의 상태/증빙 컴포넌트를 먼저 구현한다. 이것이 대상 선택→법적 근거→이행 시기→증빙→점검/요약 흐름에 직접 연결된다.
3. SCR-028~029 및 SCR-031~033은 각기 하나의 form draft/store를 공유하고 최종 저장 하나만 둔다. 스크롤 컷마다 별도 라우트, 저장 버튼, 독립 DB 트랜잭션을 만들지 않는다.
4. SCR-021~026의 관리자 CRUD는 권한·마스터·감사로그 정책이 확정된 후 단계적으로 추가한다. 용인시 영업 시연에서는 불완전한 신규/인계/삭제 버튼을 표시하지 않는다. [2] [4]
