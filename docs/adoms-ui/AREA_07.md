### 1.2 실제 업무 흐름과 컷 번호의 관계

원료·제조물 담당자의 화면 흐름은 아래와 같다. 하단 단계 버튼에서 보이는 숫자와 좌측 ①~④ 그룹 번호는 서로 다른 표기 체계이므로, 버튼 문구는 원문 그대로 노출하되 내부 라우팅은 단계 식별자로 분리해야 한다.

```text
[사업장, 부서 / 원료·제조물]
SCR-081: ① 안전보건관리 체계 구축 및 이행 > 3) 재해예방업무처리 절차 마련·이행
  → SCR-082: ② 재해발생시 재발방지 대책 수립 및 이행
     ↔ SCR-083: "산업재해, 중대산업재해 발생 이력이 없을 경우 체크하여 저장" ON 상태
  → SCR-084: ③ 중앙행정기관, 지자체 개선·시정 사항 이행
     ↔ SCR-085: "중앙행정기관, 지자체 개선·시정 사항이 없을 경우 체크하여 저장" ON 상태
  → SCR-086 / SCR-087: ④ 관계 법령 의무이행 조치의 두 하위 섹션
  → 목록으로

[사업소, 실/국 / 이행점검(사업장)]
SCR-089: 취합 대상 설정 → [취합 시작]
  → SCR-088: 의무이행(사업장) 점검 및 상태 판정
  → SCR-090: 의무이행(사업장) 점검 총괄표 → [결재하기] / [엑셀 다운로드]
```

SCR-088의 먼저 나온 화면 번호는 흐름의 선행을 의미하지 않는다. 실제로는 SCR-089의 선택값이 SCR-088의 부서 행 및 SCR-090의 사업장 열을 생성한다. SCR-090은 인덱스 캡션상 `[사업장, 부서]`이지만 명세의 상단 로그인 주체도 `하천관리과 / 김안전`으로 적혀 있어, SCR-088·089의 점검자 `푸른도시국 / 안상현`과 권한 흐름이 충돌한다. 이 화면은 결재 전 책임 주체를 확정하기 전까지 권한 기반 접근 규칙을 하드코딩하면 안 된다.[1] [2]

## 2. SCR별 기능·데이터·상태 관계

### SCR-081 — `의무이행(실적증빙) – [사업장, 부서] 원료·제조물 – 재해예방 업무처리 절차 마련·이행`

| 항목 | 분석 |
|---|---|
| 역할 | `유해 위험요인 발견 시 신고 및 개선`과 `중대시민재해 발생시 대응 조치`의 `절차도`를 두 카드에서 나란히 등록·열람한다. 이 컷은 ①의 `3) 재해예방업무처리 절차 마련·이행` 후반부다. |
| 진입 조건 | `하천관리과 / 김안전` 같은 사업장·부서 담당자가 `의무사항(실적증빙)` > `원료·제조물` > ① > `3) 재해예방업무처리 절차 마련·이행`을 선택한다. 전 단계 하단의 다음 이동 또는 좌측 스텝 네비로 진입할 수 있다. 이 컷 자체는 SCR-080 뒤의 part2이므로 별도 URL을 만들지 않는다. |
| 사용자 액션 | 카드별 `작성일자`·`PDF`·`HWP` 라디오 중 한 방식을 선택한다. 날짜를 지정하고, `찾아보기`로 파일을 고른 후 `저장`한다. 등록된 PDF는 `⬇`로 받거나 `🗑`으로 제거하고, 화면 중앙 `PDF 뷰어`에서 확인한다. `계획수립 내용 검색 및 추가`는 계획수립 문서를 검색하여 항목을 가져오는 호출부로 보인다. |
| 저장/조회 데이터 | 절차 유형 2개별로 작성일자, 제출 형식, PDF/HWP 파일 메타데이터와 바이너리, 계획수립 원본 참조를 저장한다. 화면은 저장된 `평가표.pdf`, `테스트파일입니다.pdf`, 날짜 `2023-08-04`를 조회한다. PDF는 뷰어용 URL/권한 토큰을 추가로 조회한다. |
| 이전/다음 | 이전은 `< 2단계 : 중대시민재해 예방 예산·편성·집행`, 다음은 `4단계 : 재해 발생시 재발방지대책 수립 및 이행 >`이다. 이 버튼들의 표시문구는 변경하지 않는다. |
| 같은 화면의 상태 관계 | 두 카드는 절차명만 다른 동일 컴포넌트다. `작성일자`/`PDF`/`HWP` 선택에 따른 활성 필드 상태는 하나의 페이지 내 상태다. 특히 PDF 등록 후의 `PDF 뷰어`는 별도 페이지가 아니라 같은 카드의 인라인 렌더링 상태다. |

**직접 시각 관찰:** 본문 폭 안에 두 개의 연보라·회색 카드가 수평으로 꽉 차며, 각 카드 헤더 우측에 좁은 외곽선 버튼이 있다. 카드 안의 큰 연회색 `PDF 뷰어` 빈 영역은 좌상단 굵은 라벨과 중앙 문서/이미지 플레이스홀더만 보인다. HWP 행은 뷰어 하단에서만 등장한다. 이 병렬 카드와 인라인 뷰어 조합은 이 범위에서 유일하다.[4]

### SCR-082 — `의무이행(실적증빙) – [사업장, 부서] 원료·제조물 – 재해발생시 재발방지대책 수립 및 이행` (기본 상태)

| 항목 | 분석 |
|---|---|
| 역할 | 발생 재해 단위로 `1. 상황보고서`, `2. 재발방지계획서`의 이행 실적과 증빙을 등록한다. 반복 단위는 표 행이 아니라 **발생재해 카드 전체**다. |
| 진입 조건 | 사업장·부서 담당자가 ② `재해발생시 재발방지 대책 수립 및 이행`을 선택하거나 SCR-081의 다음 단계 버튼을 누른다. 체크박스가 꺼져 있고 재해 발생 이력을 입력하는 기본 상태다. |
| 사용자 액션 | `산업재해, 중대산업재해 발생 이력이 없을 경우 체크하여 저장`을 켜거나 끈다. 카드의 `발생재해명`, `재해발생일`을 입력하고 고정 2행의 날짜·이행 내역·파일·비고를 편집한다. 행별 `+`로 증빙을 추가하며, `⬇`, `🗑`으로 증빙을 관리한다. `재해 추가`, 카드 `삭제`, 전체 `저장`을 사용한다. |
| 저장/조회 데이터 | 연도·대상별 무재해 여부와 사고 카드 배열을 저장한다. 카드에는 재해명, 발생일, 두 고정 구분, 이행일자, 이행내역, 증빙 파일 목록, 비고가 필요하다. 화면 예시는 `test`, `2023-02-01`, `선택 파일 없음`이다. 안내 `필수 내역`, `증빙자료 예시`는 정적 조회 데이터다. |
| 이전/다음 | 이전은 `< 3단계 : 재해예방업무처리 절차 마련·이행`, 다음은 원문 오타를 포함한 `5단계 : 중앙행정기관, 지자채 개선-시정사항 이행 >`이다. |
| 같은 화면의 상태 관계 | SCR-083은 이 화면의 체크 ON 상태다. 체크 ON이면 카드·`재해 추가`가 사라지고 `저장`으로 무이력 상태를 확정한다. 체크 OFF면 저장된 카드 배열을 복귀시킨다. |

### SCR-083 — `의무이행(실적증빙) – [사업장, 부서] 원료·제조물 – 재해발생시 재발방지대책 수립 및 이행` (발생 이력 없음 상태)

| 항목 | 분석 |
|---|---|
| 역할 | 재해가 없다는 예외 선언을 보여주는 **설계 주석용 상태 컷**이다. 별도 데이터 입력 페이지가 아니다. |
| 진입 조건 | SCR-082에서 `산업재해, 중대산업재해 발생 이력이 없을 경우 체크하여 저장`을 ON으로 변경한다. |
| 사용자 액션 | 체크 상태를 저장하거나 다시 OFF로 변경한다. 실제 제품에 `해당 체크 클릭 시, 아래 부분 사라짐` 말풍선과 빨간 화살표는 넣지 않는다. 이는 동작 설명을 위한 설계 주석이다. |
| 저장/조회 데이터 | SCR-082와 같은 사고 이력 데이터이며, `no_accident_history` 같은 예외 플래그를 저장해야 한다. ON 상태에서 사고 카드 입력 데이터의 삭제, 보존, 재노출 규칙은 명세에 없다. |

### SCR-088 — `이행점검 및 조치 – [사업소, 실/국] 사업장 이행점검`

| 항목 | 분석 |

| 진입 조건 | 사업소·실/국 점검자가 `이행점검(사업장)`을 새로 시작할 때 진입한다. 인덱스 part는 2지만 실제 업무 순서는 SCR-088의 선행이다. |
| 사용자 액션 | `사업장` dropdown, `사업장명` 텍스트 입력, `검색`으로 좌측 목록을 필터링한다. 좌·우 행의 원형 토글로 개별 선택/해제하고 헤더 우측 토글로 전체 선택/해제한다. `취합 시작`으로 회차를 생성하고 상세 점검으로 간다. |
| 저장/조회 데이터 | 조직/사업장 목록과 10개 점검항목 마스터를 조회한다. 선택한 대상 ID 집합과 항목 ID 집합, 필터 조건, 회차 생성 시점·생성자·상태를 `inspection`에 저장한다. 표시 예시는 부서A·D·G 선택, 1~10번 전부 선택이다. |
| 이전/다음 | 이전 화면은 명시되지 않았다. 다음은 `취합 시작` 후 SCR-088이며, 그 선택값을 근거로 SCR-090의 사업장 열 및 항목 범위가 결정된다. |
| 같은 화면의 상태 관계 | 초기/검색 결과/개별 선택/전체 선택 상태는 하나의 화면의 상태다. 좌 `사업장명`과 우 `항목` 패널은 같은 체크리스트 제어를 데이터 소스만 바꿔 재사용한다. |

### SCR-090 — `이행점검 및 조치 – [사업장, 부서] 사업장 이행점검` (의무이행(사업장) 점검 총괄표)

| 항목 | 분석 |
|---|---|
| 역할 | 점검 회차의 항목별 상태를 사업장별 매트릭스로 집계하고 이행률을 제시한 뒤 `결재하기`와 `엑셀 다운로드`를 수행하는 읽기 중심 종결 화면이다. |
| 진입 조건 | SCR-089에서 선택된 대상×항목에 대해 SCR-088 판정이 존재하는 회차를 연다. 실제 컷의 상단 로그인 주체는 `하천관리과 / 김안전`로 되어 있어, 회차 열람·결재 권한은 별도 확인이 필요하다. |
| 사용자 액션 | `결재하기`, `엑셀 다운로드`, 그리고 추정상 상태 셀 클릭을 통한 해당 상세 이동만 제공한다. 셀 자체는 직접 편집하지 않는다. |
| 저장/조회 데이터 | `inspection_item.status`를 읽어 `이행완료`→`O`, `보완필요`→`△`, `미이행`→`X`, `해당없음`→`-`로 표시한다. 행별 전체/상태별 건수, 사업장별 이행률을 계산 조회한다. `결재하기`는 회차 결재 상태·결재선·확정 시각·결재자를 저장하며, 엑셀은 이 조회 모델을 xlsx로 내보낸다. |
| 이전/다음 | 화면상 단계 이동은 없다. 결재 상신/완료가 후속 업무이고, `보완필요`·`미이행`은 하위 부서 의무이행 보완 및 SCR-088 재점검 루프로 연결된다. |
| 같은 화면의 상태 관계 | SCR-089의 선택 부서 수에 맞추어 `사업장` 하위 열이 가변 생성된다. SCR-088의 판정 변경, 회차 미결재/결재상신/결재완료 상태 및 엑셀 추출은 동일 총괄표 route의 상태다. 3개 열을 고정하지 않는다. |

**직접 시각 관찰 및 산식 검증:** 상단 우측에 `결재하기`, `엑셀 다운로드`가 가로로 붙는다. 표는 `점검사항` 고정 첫 열 다음에 `사업장` 3열, `전체항목`, 상태 집계 4열이 이어지는 2단 헤더다. `O`는 연파랑, `△`는 연노랑, `X`는 연주황, `-`는 흰색이다. 제공값은 부서A `8/9 = 88.8%`, 부서D `7/8 = 87.5%`, 부서G `7/9 = 77.7%`와 맞아 `해당없음 (-)`을 분모에서 제외한 이행완료 비율로 보인다. 표기 방식이 반올림인지 절사인지는 확정되지 않았다.[13]

## 8. 구현 우선순위와 데이터 연결 결론

용인시 영업 시연의 최소 신뢰 가능한 경로는 **SCR-089 → SCR-088 → SCR-090**이다. 이 세 화면은 대상 선택, 증빙 검토와 상태 판정, 경영진 결재용 집계를 하나의 자연스러운 이야기로 연결한다. 원료·제조물 의무이행 화면은 피점검 부서의 보완 화면으로 연결하되, 기본 시연에서는 SCR-081, SCR-082, SCR-086/087을 증빙 유형이 서로 다른 대표 장면으로 사용하면 충분하다.

데이터는 화면 단위 사본이 아니라 관계로 연결해야 한다. `inspection`에는 선택된 부서·항목과 회차·결재상태를, `inspection_item`에는 교차 단위 판정과 `점검내용`을, 원 이행 데이터에는 원료·제조물의 항목별 상세 입력과 `duty_evidence` 파일을 저장한다. SCR-090은 원본을 중복 저장하지 않고 `inspection_item` 상태를 집계해야 한다. 이 구조라야 SCR-088 재점검 후 SCR-090이 자동 갱신되며, SCR-089의 선택에 따라 매트릭스의 사업장 열이 안전하게 가변된다.[2] [3]
