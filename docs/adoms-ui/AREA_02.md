# AREA_02 — 이행현황 화면 분석

> **분석 범위:** `SCR-010` ~ `SCR-020` (11개 화면 컷)
> **대상 영역:** 이행현황 — 총괄·담당부서의 조회·집계·조치 지시
> **분석 기준:** 화면 인덱스의 정식 화면명, 개별 화면 명세, 그리고 번호 흐름에 따라 `010`부터 `020`까지의 원본 PNG를 각각 직접 육안 검토하였다. 모든 이미지는 2001 × 1127 px의 데스크톱 화면 캡처이다. [1] [2] [3]

## 결론

이 영역은 하위 담당자가 입력한 의무이행 결과를 경영책임자 또는 총괄이 **조회·집계·비교하고, 미흡 대상에 조치 지시를 보내는 읽기 중심 영역**이다. 11개 SCR은 11개의 독립 페이지가 아니다. 실질적인 페이지 골격은 취합 대상 선택, 전체 집계표, 대상별 비교표, 도급·용역·위탁 선택, 계약 아코디언 매트릭스의 다섯 가지이며, `SCR-013`, `SCR-017`, `SCR-020`은 각각 기존 화면 위에 열린 **상태 레이어**이다.

구현은 한 화면군을 세 벌로 복제하지 않고 `disasterType`, `targetAxis`, `showTargetColumns`, `selectionMode` 등의 파라미터로 재사용해야 한다. 특히 `SCR-011`/`SCR-015`, `SCR-012`/`SCR-016`, `SCR-013`/`SCR-017`은 데이터 축과 라벨만 다른 동형 화면이다. 용인시 영업 시연에서는 기존 7개 라우트를 넘기지 않고, 이 영역의 핵심은 `/summary`와 `/targets`의 **뷰 상태 및 모달 상태**로 흡수하는 것이 적절하다.

| 구분 | 판정 |
|---|---|
| 화면 컷 수 | 11개 (`SCR-010`~`SCR-020`), 모두 원본 이미지 직접 확인 |
| 독립 라우트로 취급할 기본 화면 | 5개 골격: 취합 선택, 전체 집계, 대상별 비교, 도급 선택, 도급 계약 매트릭스 |
| 별도 라우트로 만들면 안 되는 상태 | `SCR-013` = `SCR-012`의 조치 지시 모달, `SCR-017` = `SCR-016`의 조치 지시 모달, `SCR-020` = `SCR-019`의 계약 상세 오버레이 |
| 이행 상태 | `이행완료(O)` / `보완필요(△)` / `미이행(X)` / `해당없음(-)`; 도급·용역·위탁 매트릭스는 `O` / `X`만 사용 |
| 핵심 데이터 방향 | `duty_record`·의무항목·조직/대상 마스터를 읽어 자동 집계하고, 조치 지시를 사용하면 `action_order`와 수신/발신 이력을 기록 |

## 1. 화면 흐름과 상태 관계

### 1.1 주 흐름

```text
[중대산업재해]
SCR-010 취합 대상 설정
  └─ [취합 시작] → SCR-011 전체 이행 현황표
                     └─ [전체보기] → SCR-012 대상별 이행 현황표
                                           └─ [메시지 보내기] → SCR-013 조치 지시 모달

[중대시민재해]
SCR-014 취합 대상 설정
  └─ [취합 시작] → SCR-015 전체 이행 현황표
                     └─ [전체보기] → SCR-016 대상별 이행 현황표
                                           └─ [메시지 보내기] → SCR-017 조치 지시 모달

[도급·용역·위탁]
SCR-018 사업장 선택
  └─ [도급·용역·위탁 현황 보기] → SCR-019 계약별 이행 현황표
                                       └─ [계약명] → SCR-020 계약 기본정보 오버레이
```

`SCR-011`과 `SCR-012`, `SCR-015`와 `SCR-016`은 동일 집계 데이터의 **요약/대상별 확장 뷰** 관계다. `SCR-013` 및 `SCR-017`은 각각 직전 대상별 표를 흐리게 남긴 채 열리는 모달이며, `SCR-020`도 `SCR-019`의 계약 목록을 배경에 보존한 우측 상세 카드다. 따라서 모달·오버레이를 라우팅하거나 새 페이지로 구현하면 원본의 맥락이 훼손된다. 명세에는 대상별 표에서 요약표로 돌아가는 전용 버튼 또는 브라우저 뒤로가기 외의 이전 동작이 명시되지 않았다.

### 1.2 화면 컷과 실제 페이지 패턴의 대응

| 실제 패턴 | 해당 SCR | 라우트/상태 판단 |
|---|---|---|
| 2단 취합 대상 선택 | `SCR-010`, `SCR-014` | 하나의 `CollectionTargetPicker` 페이지에 재해 유형·대상 축·라벨을 주입한다. |
| 전체 이행 현황 집계표 | `SCR-011`, `SCR-015` | 하나의 `ComplianceSummaryTable` 페이지. `showTargetColumns=false` 상태다. |
| 대상별 이행 현황 매트릭스 | `SCR-012`, `SCR-016` | 위 집계표의 `showTargetColumns=true` 확장 상태 또는 동일 라우트의 뷰 전환 상태다. |
| 조치 지시 전송 | `SCR-013`, `SCR-017` | 대상별 매트릭스의 `ActionOrderModal` 오버레이 상태다. 독립 페이지가 아니다. |
| 단일 사업장 선택 | `SCR-018` | 취합 대상 선택기의 단일 패널 변형이지만, 원본 시각 구조상 별도 선택 패턴으로 둔다. |
| 계약별 O/X 아코디언 | `SCR-019` | `ContractComplianceAccordion` 페이지다. 일반 이행률 집계표와 혼합하지 않는다. |
| 계약 기본정보 | `SCR-020` | 계약별 O/X 아코디언의 `selectedContractId` 읽기전용 상세 카드 상태다. 독립 페이지가 아니다. |

## 2. SCR별 상세 명세

### SCR-010 — `이행현황 – [총괄, 담당부서] 중대산업재해 : 대상 및 취합정보 항목 선택`

| 항목 | 분석 |
|---|---|
| 역할 | 중대산업재해의 집계 대상인 의무 대분류와 `사업장`을 다중 선택하는 시작 화면이다. 본문 제목은 `취합 대상 설정`이다. |
| 진입 조건 | `이행현황`에서 좌측 메뉴 `중대산업재해`의 `사업장`을 선택한 총괄·담당부서/경영책임자 맥락이다. 헤더 표기는 `시장(경영책임자)` / `나사장`이다. 이전 화면이나 URL은 명세에 확정되지 않았다. |
| 사용자 액션 | `사업장` select, `사업장명` 입력, `🔍검색`, 의무행과 사업장 행의 원형 체크 토글, 각 패널 우측 `⌄`, 하단 `⌄⌄`, 그리고 `취합 시작`을 사용한다. `취합 시작`은 `SCR-011`로 이동한다. |
| 저장/조회 데이터 | `안전·보건 확보의무` 대분류와 사업장 마스터를 조회한다. 선택 결과는 다음 화면 조회 조건으로 전달되어야 하나, 서버에 취합 회차를 생성하는지와 영구 저장 여부는 명시되지 않았다. 기본 예시에서는 1번과 4번 의무, 10개 사업장이 선택되어 있다. |
| 이전/다음 화면 | 이전: 별도 정의 없음(메뉴 진입/브라우저 이전). 다음: `SCR-011`. |
| 같은 화면의 상태 관계 | 검색어·필터·선택 ID·패널 펼침 상태를 가진 단일 선택 화면이다. `SCR-014`와 골격은 같고, 라벨과 데이터 소스만 다른 파라미터 변형이다. |

**육안 확인:** 회색의 길고 둥근 검색 바 아래에 너비가 거의 같은 흰색 패널 두 장이 놓인다. 좌측 `안전·보건 확보의무`에는 큰 행 4개, 우측 `사업장`에는 번호가 붙은 조밀한 목록 10개가 있다. 선택 원형은 진한 파랑, 미선택 원형은 옅은 회색이고, 우측 목록에는 실제 세로 스크롤바가 보인다.

### SCR-011 — `이행현황 – [총괄, 담당부서] 중대산업재해 : 선택항목에 대한 해당년도 이행 현황표`

| 항목 | 분석 |
|---|---|
| 역할 | 선택 의무항목에 대한 해당 연도 전체 이행률과 `O`/`△`/`X`/`-` 건수를 요약하는 집계표다. |
| 진입 조건 | `SCR-010`에서 `취합 시작`을 누른 후의 중대산업재해 사업장 범위·선택 항목·연도 조건이다. 기본 `년도`는 `2023`이다. |
| 사용자 액션 | `년도`를 변경해 재조회하고, 대분류 행의 `⌄`으로 하위 소항목을 접거나 펴며, `엑셀다운로드`를 누르고 `전체보기`로 대상별 확장 뷰를 연다. |
| 저장/조회 데이터 | 선택된 사업장·의무항목·연도에 대한 `duty_record.status`를 조회하고, 대분류/소항목별 `전체항목`, 상태별 건수 및 이행률을 계산한다. 엑셀은 현재 필터 결과를 내보내는 다운로드 산출물이다. 이 화면 자체의 변경 저장은 없다. |
| 이전/다음 화면 | 이전: `SCR-010`의 선택 조건 변경. 다음: `전체보기`로 `SCR-012`; 엑셀은 파일 다운로드다. |
| 같은 화면의 상태 관계 | `SCR-012`의 대상 컬럼이 없는 요약 상태다. `SCR-015`와 표 구조는 동일하며 점검사항 마스터만 중대시민재해용으로 바뀐다. |

**표 구조:** 컬럼은 `점검사항`, `이행률`, `전체항목`, `이행완료 (O)`, `보완필요 (△)`, `미이행 (X)`, `해당없음 (-)` 순이다. 대분류 행은 수치 없이 굵게 보이고, 소항목은 들여쓴다. 마지막 `이행률` 합계 행에는 `78%`만 표시한다. `100%`/`70%`/`50%`/`33%` 셀의 녹색·노랑·연분홍 배경이 시선의 중심이다.

### SCR-012 — `이행현황 – [총괄, 담당부서] 중대산업재해 : 선택항목에 대한 대상별 이행 현황표`

| 항목 | 분석 |
|---|---|
| 역할 | `SCR-011`의 상태별 집계를 유지하면서 `사업장`별 상태를 한 표에서 비교하고, 조치 지시의 출발점이 된다. |
| 진입 조건 | `SCR-011`에서 `전체보기`를 선택한 상태다. 기본 `년도`는 `2023`이며 선택 사업장 집합이 대상 컬럼을 결정한다. |
| 사용자 액션 | `년도` 재조회, `엑셀다운로드`, 대분류 `⌄` 접기/펼치기, 하단 가로 스크롤 또는 우측 `»`, 그리고 `메시지 보내기`를 사용한다. 마지막 버튼은 `SCR-013` 모달을 연다. |
| 저장/조회 데이터 | 전체 집계 데이터에 사업장별 `duty_record.status`를 피벗해 읽는다. `소방서`, `어린이병원`, `서울도서관`은 화면상 보이는 일부 열일 뿐이며, 선택 수에 따라 열 수는 가변이어야 한다. 메시지 발신 전까지 화면 자체는 조회다. |
| 이전/다음 화면 | 이전: `SCR-011`의 요약 상태(역방향 전환 방식은 미정). 다음/상태: `SCR-013` 모달. |
| 같은 화면의 상태 관계 | `SCR-011`의 확장 상태다. `SCR-016`과 완전히 동형이며 병합 헤더 `사업장`만 `실·국·본부`로 바뀐다. |

**표 구조:** 공통 7개 집계 컬럼 뒤에 병합 헤더 `사업장`과 2단 헤더가 붙는다. 사업장별 상태 셀은 `O`와 `-`은 연파랑, `△`는 연노랑, `X`는 연분홍으로 채운다. 표가 본문 폭을 넘기므로 우측 `»`와 하단의 굵은 회색 가로 스크롤 트랙을 반드시 둔다. 좌하단의 `메시지 보내기`는 작은 회색 입체 버튼이다.

### SCR-013 — `이행현황 – [총괄, 담당부서] 중대산업재해 : 이행현황 확인에 따른 조치 지시`

| 항목 | 분석 |
|---|---|
| 역할 | 이행률이 낮은 `사업장`을 수신자로 고르고 개선 조치 문구를 발신하는 상태다. |
| 진입 조건 | `SCR-012`에서 `메시지 보내기`를 누른 상태다. 배경의 대상별 매트릭스는 유지하고 반투명 회색 오버레이로 비활성화한다. |
| 사용자 액션 | `메시지 발신 목록`, `🔍 검색`, 후보 행 `추가`, 선택 행 `제외`, `선택 완료`, `메시지` textarea 입력 및 `발신`이 있다. |
| 저장/조회 데이터 | 후보 사업장과 이행률을 읽고, `추가`/`제외`는 임시 수신자 목록을 바꾼다. `선택 완료`의 확정 의미와 `발신` 성공 시에는 `action_order` 본문·발신자·수신자·발신시각·원본 조회조건을 저장하고 알림/발신 이력을 생성하는 설계가 필요하다. `메시지 발신 목록`의 데이터 범위는 미정이다. |
| 이전/다음 화면 | 이전: `SCR-012`; 닫기/취소 컨트롤은 원본에 보이지 않아 동작 정의가 필요하다. 다음: 발신 완료 화면 또는 토스트가 명시되지 않았으므로 발신 뒤 동일 `SCR-012` 상태로 복귀시키는 것이 안전하다. |
| 같은 화면의 상태 관계 | 독립 페이지가 아닌 `SCR-012`의 모달 상태다. `SCR-017`과 동일한 `조치지시모달`이며 대상 축만 다르다. |

**육안 확인:** 모달은 화면 중앙의 넓은 흰색 사각형이며 얇은 남색 외곽선과 회색 차광층을 사용한다. 좌우의 3열 표(`사업장`/`이행률`/`선택`) 사이에는 노란색 굵은 `⇨`가 있다. `60.00%`·`68.76%`는 연분홍, `72.20%`는 연노랑, `83.66%`는 연녹이다. 배경 하단 `메시지 보내기`에서 모달로 향하는 빨간 화살표는 설계 주석이므로 제품 UI에 넣지 않는다.

### SCR-014 — `이행현황 – [총괄, 담당부서] 중대시민재해 : 대상 및 취합정보 항목 선택`

| 항목 | 분석 |
|---|---|

### SCR-019 — `이행현황 – [총괄, 담당부서] 도급·용역·위탁 : 선택항목에 대한 이행 현황표`

| 진입 조건 | `SCR-018`에서 `도급·용역·위탁 현황 보기`를 누른 후다. 첫 사업장 `OO시립대학교`가 열린 아코디언 상태다. |

### SCR-020 — `이행현황 – [총괄, 담당부서] 도급·용역·위탁 : 선택항목에 대한 상세 정보`

| 항목 | 분석 |
|---|---|
| 역할 | 선택 계약의 `1. 계약 기본정보`를 읽기전용으로 보여 주는 상세 카드다. |
| 진입 조건 | `SCR-019`의 `2022년 교내 전기시설물 유지보수공사(연간단가)` 계약명을 누른 상태다. |

## 3. 공통 셸 및 재사용 컴포넌트

### 3.1 이 영역의 공통 셸

모든 11개 이미지에는 상단 연녹색 경영 배너, 검정 GNB, 연녹색 좌측 메뉴, 검정 본문 캔버스와 밝은 푸터가 반복된다. 배너 문자열은 `경영목표`, `통합된 안전보건관리체계 확립으로 중대산업재해 ZERO 달성`, `경영방침`, `‖`, `1. 안전문화 정착`이다. GNB 로고 텍스트는 `OO광역시 │ 안전보건체계 통합관리시스템`이며, `이행현황`이 녹색 활성 상태다. 우측 사용자 영역의 `시장(경영책임자)`, `나사장`, `정보수정`, `로그아웃`도 동일하다.

### 4.2 표·상태 색·범례

| 시각 요소 | 원본 표현 | 구현 유의점 |
|---|---|---|
| 이행률 셀 | `우수 (80% 이상)`은 연녹, `보통 (70% 이상)`은 연노랑, `미흡 (70% 미만)`은 연분홍/피치 | 색은 텍스트 배지가 아니라 셀 배경 전체에 깐다. 정확한 계산 규칙은 설정값으로 둔다. |
| 대상별 상태 | `O` 및 `-` 연파랑, `△` 연노랑, `X` 연분홍 | 상태 텍스트는 중앙 정렬하고, 상태명 대신 표 안에는 기호만 보인다. |

### 4.3 버튼·아이콘·오버레이

일반 버튼은 현대적인 채움형 CTA보다 **얇은 회색 테두리, 흰/옅은 회색 면, 미세한 입체 그림자**가 있는 레거시 공공업무 화면의 형태다. `엑셀다운로드`만 녹색 이중 테두리/강조로 보이고, `전체보기`, `취합 시작`, `메시지 보내기`, `선택 완료`, `발신`은 중성 회색 버튼이다. 선택 토글은 파란 원 안의 흰 V이고, 접기·펼치기는 회색 또는 녹색 V/`⌄`다.

모달은 전체 화면을 반투명 중회색으로 가리고, 중앙에 넓은 흰 패널을 올린다. 패널 내부는 표와 메시지 입력 영역을 명확히 나누되, 대형 제목줄이나 별도 장식은 없다. 원본에 닫기 X가 보이지 않으므로 임의로 강한 닫기 버튼을 만들지 말고 접근성상 필요한 닫기 동작은 발주처 확인 뒤 추가한다. `SCR-013`, `SCR-017`, `SCR-020`의 빨간 화살표·파란 설명 상자는 시연 화면에 재현하지 말아야 할 문서 주석이다.

## 5. 용인시 영업 시연 적용 판단

용인시 데모는 `dashboard → target → legal basis → obligation due date → evidence → inspection → correction → summary`의 고정된 7개 라우트를 유지해야 한다. 이 화면군을 11개 신규 라우트로 늘리지 않는다. 공공기관 시각 언어(연녹 목표띠·검정 GNB·연녹 LNB·회색 검색 패널·조밀한 표·`O/△/X/-`)는 그대로 사용하되, `OO광역시`, `OO시립대학교`, 서울시식 조직 예시는 용인시 시나리오 데이터로 바꾼다. [4]

| SCR | 용인시 시연 판단 | 적용 방식 |
|---|---|---|
| `010` | **상태 재사용** | `/targets`에서 `track=산업`과 다중 대상·의무 선택 상태로 사용한다. 별도 `취합 대상 설정` 라우트는 만들지 않는다. |
| `011` | **사용** | `/summary`의 경영책임자용 전체 집계 뷰로 사용한다. 저장된 `duty_record`에서 동적으로 계산한다. |

| `013` | **조건부 사용** | 실제 `action_order` 저장·수신 이력·성공 피드백이 연결된 경우에만 `/summary` 모달로 사용한다. 연결하지 않을 경우 `메시지 보내기`는 숨기거나 비활성으로 명시한다. |

| `018` | **상태 재사용** | 계약 시나리오를 데모에 포함할 때 `/targets?mode=contract`의 단일 패널 목록으로 흡수한다. 계약 시드가 없다면 메뉴 진입 자체를 숨긴다. |

| `020` | **상태 재사용 또는 숨김** | `SCR-019` 내 읽기전용 side card로만 연다. 계약·첨부 실데이터가 없으면 노출하지 않고, 더미 `+` 첨부 버튼을 클릭 가능하게 남기지 않는다. |

이행률은 데모에서도 저장된 상태에서 계산한다. `해당없음`은 분모에서 제외하고, 등급 임계값은 설정값으로 둔다. 데모의 법령 참조는 읽기전용, 조치·증빙·점검 같은 업무 기록은 쓰기 가능해야 하며, 조치 지시·첨부 추가·다운로드처럼 구현되지 않은 행동은 클릭 가능한 장식으로 남기지 않는다. [4]

| 15 | 문서 주석의 제품 반영 제외 | `013`, `017`, `020` | 빨간 연결선·파란 메모 상자는 와이어프레임 설명이다. 시연/운영 UI에서 제거하는 것을 확인한다. |

## 7. 구현 데이터 연결 요약

| 화면군 | 읽기 모델 | 쓰기 모델 | 계산/보안 핵심 |
|---|---|---|---|
| 취합 대상 선택 | `target`, `org`, `duty_item`, 사용자 권한별 대상 범위 | 확정 시 `inspection` 또는 조회 조건 세션 | 조직·재해유형·역할에 맞는 대상만 노출한다. |
| 전체/대상별 이행 현황 | `duty_record`, `duty_item`, `target`, `org` | 없음; 엑셀 산출물만 생성 | 연도·재해 트랙·선택 대상·의무를 조건으로 하고, 상태별 건수과 이행률을 동일 계산 함수에서 만든다. |
| 조치 지시 | 대상별 이행률, 과거 `action_order` | `action_order`, 수신자 매핑, `notification`, 감사 로그 | 수신 대상과 표를 본 시점의 스냅샷을 저장하고, 권한 없이 전 기관에 발신하지 못하게 한다. |
| 도급 계약 현황/상세 | `contract`, 계약별 관리의무 결과, 첨부 메타데이터 | 조회 모드 없음; 편집 권한 확정 시 계약/첨부 모델 | `contract_id`로 상세를 열고 첨부는 비공개 저장소의 권한 확인 뒤 다운로드/미리보기한다. |
