# AREA 01 — 정보구조·권한·대시보드 분석

**대상 범위:** SCR-001~SCR-009
**작성자:** Manus AI
**분석 기준:** 화면 원문 라벨을 변경하지 않고, 화면 명세·인덱스·원본 PNG를 함께 대조하였다. 이미지 폴더에는 `img001.png` 형식 파일 대신 번호가 유지된 한글 파일명(`001_메뉴구조도.png` 등)이 존재하므로, 번호별 대응 파일 9장을 직접 열어 판독하였다. 대상 이미지는 SCR-001~004가 1079~1403px 폭의 다이어그램이고, SCR-005~009가 2001×1127px의 데스크톱 시안이다. [1] [2] [3]

> **결론:** 이 영역의 9개 컷은 사용자용 실제 페이지 9종이 아니다. `SCR-001~004`는 메뉴·권한을 확정하기 위한 정적 설계 참조물이고, 실제 운영 화면은 **비로그인 `로그인` 1종** 및 **권한·조직 범위만 다른 `메인(대시보드)` 1종**으로 압축된다. 따라서 용인시 영업 시연은 하나의 공통 셸, 하나의 대시보드 위젯 조합, 네 개의 사용자 컨텍스트 상태로 구현하는 것이 원본에 가장 충실하다.

## 1. 범위, 번호 흐름, 상태 관계

이미지 파일명 기준 흐름은 `001 → 002 → 003 → 004 → 005 → 006/007/008/009`이다. 단, 개별 명세의 도입부 표기는 `SCR-002`를 “part1”, `SCR-001`을 “part2”로 역순 표기한다. 두 컷은 서로 다른 정적 다이어그램이며 웹 라우트나 한 페이지의 스크롤 상·하단이 아니다. 이 역순 표기는 발주처 확인 항목으로 남긴다.

`SCR-006~009`는 화면 구조가 같은 **동일 대시보드 라우트의 권한/데이터스코프 상태**다. 각기 별도 페이지를 만들지 않는다. `SCR-006`과 `SCR-007`은 집계 수치도 같고 헤더 사용자와 `알림` 문구만 다르며, `SCR-008`과 `SCR-009`은 동일 위젯에 조직 범위가 축소된 데이터가 주입된 상태다. 이 범위에는 모달, 편집 상태, 또는 계속(스크롤 하단) 화면으로 판독되는 별도 컷은 없다.

## 2. SCR별 기능·전이·데이터 명세

### 2.1 대시보드 데이터스코프와 시연용 상태값

모든 대시보드에서 `년도` 기본값은 `2023`, `대상` 기본값은 `공중이용시설`이다. 표의 UI 라벨은 `의무이행`, `전체`, `상반기`, `하반기`, `이행률`, `이행완료`, `보완필요`, `미이행`, `해당없음`, `합 계`로 유지해야 한다. 아래 수치는 시안의 더미 데이터이므로 정책·임계값 로직에 하드코딩하지 않는다.

## 4. 공통 셸, 재사용 컴포넌트, 데이터 계약

### 4.1 공통 셸

`SCR-005~009`은 모두 `TopBanner`와 `Footer`를 공유한다. `TopBanner`에는 `경영목표`, `통합된 안전보건관리체계 확립으로 중대산업재해 ZERO 달성`, `경영방침`, `‖`, `1. 안전문화 정착`이 가로 한 줄로 고정된다. `Footer`에는 북부청사·남부청사 주소 및 `Copyright ⓒ OO METROPOLITAN CITY ALL RIGHTS RESERVED.`가 작은 회색 글씨로 놓인다.

로그인 뒤의 `AppHeader`에는 좌측 로고 `OO광역시 │ 안전보건체계 통합관리시스템`, 중앙 GNB, 우측 소속/직위·사용자명·`정보수정`·`로그아웃`이 있다. GNB의 원문 순서는 `이행현황` / `관리대상 현황` / `법 의무사항` / `의무이행(실적증빙)` / `이행점검 및 조치` / `기관장 예방활동` / `통계 및 사례` / `관리자`다. 반면 `로그인`은 GNB와 사용자영역을 빼고 로고만 중앙 정렬한 `PublicHeader` 상태다.

이 대시보드 범위에서는 **좌측 내비게이션 사이드바가 없다.** 좌측의 큰 연녹색 영역은 내비게이션이 아니라 `담당 중대재해 대상` 위젯이다. 이후 업무 입력 화면의 2단 사이드바를 대시보드에 잘못 적용하지 않는다.

## 5. 육안 복제 포인트

### 5.1 전체 인상과 밀도

원본은 넓은 데스크톱 고정형 시안이다. 상단은 얇고 정보량이 높으며, 대시보드는 왼쪽의 세로 대상 패널, 중앙의 마감·이행률·표, 오른쪽의 `알림`·2×2 의무카드가 병렬로 놓인다. 모바일 우선 카드 스택이나 여백이 큰 SaaS 스타일로 바꾸면 원본의 공공 행정 대시보드 밀도가 사라진다. 2001×1127 기준 시안의 비율을 기준으로 넓은 컨테이너, 촘촘한 12~16px급 표/보조문자, 명확한 테두리를 유지한다.

이미지 추출본은 투명 픽셀이 많아 뷰어에서 빈 영역이 검정으로 보인다(`SCR-005` 약 79%, `SCR-006~009` 약 42% 투명). 이 검정은 다크 테마 배경으로 복제할 근거가 아니다. 실제 구현은 흰색 또는 아주 연한 중성색 본문 배경을 명시하고, 투명 추출 아티팩트에 의존하지 않는다.

## 6. 용인시 영업 시연 적용 판단

원본 라벨은 분석 및 서울시 화면 충실 복제의 기준으로 유지한다. 아래 ‘용인시 시연’ 판단은 화면을 실제 영업 시나리오에 넣을 때의 제품 노출 전략이며, 기관명·주소·사용자명·대상명·연락처와 더미 수치는 용인시 맥락의 승인된 fixture로 교체해야 한다.

| SCR | 용인시 영업 시연 판단 | 근거와 구현 방식 |
|---|---|---|
| SCR-001 | **숨김(내부 설계 참조로 사용)** | 최종 사용자의 기능이 아닌 설명표다. 제안서 부록 또는 내부 구현 검증에는 사용하되 제품 메뉴에서 노출하지 않는다. 영업 미팅에서 기능 범위 소개가 필요할 때만 정적 슬라이드로 사용한다. |
| SCR-002 | **숨김(IA·GNB 설계 원천으로 사용)** | 대화형 서비스 페이지가 아니다. 다만 `관리대상 현황`~`시스템 관리자`의 계층을 용인시 메뉴 설계와 데모 스토리의 기반으로 재사용한다. |
| SCR-003 | **숨김, 권한 시연의 백엔드 근거로 사용** | ①~⑤ 온보딩을 ‘담당자 지정 → 대상 등록 → 의무/증빙 → 점검’ 이야기 순서로 재사용한다. 공개 GNB에서는 숨기고, 필요하면 관리자 설정 설명에서만 보여 준다. |
| SCR-004 | **숨김, RBAC 상태 재사용** | 권한코드·재해유형 2차원 모델을 사용한다. 영업 시에는 코드 대신 `경영책임자`, `중대재해 담당부서`, `사업소, 실/국`, `사업장, 부서` 페르소나 전환으로 보여 주는 편이 이해가 쉽다. |
| SCR-005 | **사용(브랜딩·문의처 교체)** | 로그인 진입을 재사용한다. 업무포탈 경유 사용등록 문구, 기관 연락처, 로고, 저작권은 용인시의 실제 정책 확정 뒤 바꾼다. 빠른 시연을 위해 4개 페르소나 선택을 보조적으로 두더라도 원본의 단순 폼 흐름을 훼손하지 않는다. |
| SCR-006 | **사용(핵심 경영진 시연 상태)** | 가장 강한 총괄 스토리다. `기한 초과`, `오늘 마감`, `전체 이행률`, 4개 의무카드를 경영진 KPI로 제시한다. 전 기관 스코프 fixture를 주입한다. |
| SCR-007 | **상태 재사용(별도 페이지 금지)** | SCR-006과 같은 UI에 `안전총괄과` 컨텍스트만 넣는다. 총괄부서가 경영진과 같은 전체 현황을 보고 후속 점검을 수행한다는 스토리에 사용한다. |
| SCR-008 | **상태 재사용(조직장 시연 상태)** | 같은 UI에 소관 조직 fixture를 넣어 ‘전사→실국’으로 좁아지는 데이터스코프를 시연한다. 대상 트리와 기한초과가 축소되는 비교가 핵심이다. |
| SCR-009 | **상태 재사용(현장 담당자 시연 상태)** | 동일 UI에 본인 지정 대상만 주입해 실행 주체 관점을 보여 준다. 단, `관리자` GNB는 권한 확정 전에는 숨김 또는 disabled로 두고 실제 접근은 차단한다. |

시연의 주 흐름은 **로그인 → 경영책임자 전체 현황(SCR-006) → 총괄부서 동일 스코프(SCR-007) → 실·국 스코프 축소(SCR-008) → 담당자 지정 대상(SCR-009) → 필요 시 `의무이행(실적증빙)` GNB으로 후속 증빙 화면**이다. 마지막 GNB 목적지는 본 분석 범위 밖이므로 이 보고서에서는 라우트 계약만 정의한다.

## 8. 구현 인수 기준

1. `SCR-006~009`은 URL 네 개가 아니라 한 `DashboardPage`여야 하며, URL/세션의 사용자 컨텍스트만 바꾸면 위젯 구조가 유지되어야 한다.
2. 모든 대시보드에서 `년도`, `대상`, `이행완료`, `보완필요`, `미이행`, `해당없음`, `합 계`, `우수`, `보통`, `미흡`의 원문 표기를 그대로 쓴다.
3. 경영책임자·총괄부서는 전 기관, 사업소·실/국은 소관 하위, 사업장·부서는 지정 관리대상이라는 데이터 필터가 서버 조회에도 적용되어야 한다.
4. `기한 초과`는 적색 경고카드, 대시보드 왼쪽 대상목록은 데이터 길이에 따라 내부 스크롤/`≫`를 조건부 렌더링해야 한다.
5. 로그인 전후의 로고 정렬, GNB·사용자영역 존재 여부, 공통 `TopBanner`/`Footer`는 화면 상태에 따라 정확히 전환되어야 한다.
6. 본문은 검정 투명 영역을 다크 테마로 오인하지 않고, 원본과 같은 밝은 배경·연녹색 패널·조밀한 표 레이아웃으로 렌더링해야 한다.
