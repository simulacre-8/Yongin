# AREA 06 — 의무이행(실적증빙): 공중이용시설 후반·원료·제조물 전반 UI 분석

**분석 범위:** SCR-067~SCR-080
**원본 화면 컷:** 14개 (`img067.png`~`img080.png`, 모두 2001×1127px 직접 확인)
**분석 결론:** 14개는 별도의 14개 페이지가 아니다. 범위에서 확인되는 실제 업무 페이지는 **6개 패턴**이며, 나머지는 같은 라우트의 `해당없음` 상태, 모달 오픈 상태 또는 수직 스크롤 상태이다. 특히 SCR-070~074는 **단일 화면 + 모달 두 종류 + 호출 컨텍스트**이고, SCR-077~079는 **단일 예산 입력 화면의 상단·모달·하단**이다.

> **원문 보존 원칙:** 이하의 버튼, 항목명, 단계명, 안내 문구는 화면 명세의 문자열을 그대로 기록했다. `지자채`, `개선-시정사항`, `보수보강비`, `의무이행(공중이용시설)`처럼 문맥상 맞지 않거나 오기로 보이는 표기도 원문 UI를 복제할 때 임의 수정하지 않는다. 주황색 말풍선과 붉은 화살표는 기능 설명을 위한 **설계 주석**이므로 최종 서비스 화면에는 렌더링하지 않는다.

## 2. 화면 간 주 흐름과 라우트/상태 관계

### 2.1 공중이용시설·교통수단 후반 흐름

`② 재해발생시 재발방지 대책 수립 및 이행`의 기존 기본 화면(SCR-066)에서 `해당없음`을 선택하면 **SCR-067 상태**가 된다. 해제하면 원래 재해 카드가 즉시 다시 나타난다. 다음 단계로 `③ 개선·시정 등을 명한 사항 이행`에 진입하면 **SCR-068 기본 상태**이고, 여기서 해당없음을 선택한 상태가 **SCR-069**이다. 이어 `④ 관계 법령상 의무 이행`은 **SCR-070 기본 상태**로 진입한다. 그 한 화면 위에서 블록 A 또는 블록 B의 법령 검색/계획 불러오기를 열면 각각 SCR-071, 072, 073, 074가 된다. 마지막 단계의 다음 행동은 `목록으로 >`이다.

```text
SCR-066 기본(범위 밖) ── 해당없음 ON/OFF ── SCR-067 상태
          │ 다음
          ▼
SCR-068 개선·시정 기본 ── 해당없음 ON/OFF ── SCR-069 상태
          │ 다음
          ▼
SCR-070 관계 법령 기본
  ├─ 블록A 법령 검색 → SCR-071 → 선택값을 블록A에 매핑
  ├─ 블록A 계획 불러오기 → SCR-072 → 선택 행을 블록A에 매핑
  ├─ 블록B 법령 검색 → SCR-073 → 선택값을 블록B에 매핑
  └─ 블록B 계획 불러오기 → SCR-074 → 선택 행을 블록B에 매핑
          │
          ▼
       목록으로
```

### 2.2 원료·제조물 초반 흐름

원료·제조물 트랙은 좌측 `① 안전보건관리체계 구축 및 이행`에 세 개의 하위 항목만 둔다. `1) 안전인력 확보`의 **SCR-075 기본 상태**에서 계획 불러오기를 열면 **SCR-076**이다. 다음 `2) 중대시민재해 예방 예산·편성·집행`의 **SCR-077 상단**에서 불러오기 모달을 열면 **SCR-078**이고, 동일 페이지를 아래로 스크롤한 구간이 **SCR-079**이다. 이후 `3) 재해예방업무처리 절차 마련·이행`의 **SCR-080**으로 진행한다. 따라서 SCR-079는 독립 라우트나 별도 단계가 아니다.

```text
SCR-075 안전인력 기본 ── 계획 불러오기 모달 ── SCR-076
       │ 다음
       ▼
SCR-077 예방 예산 상단 ── 예산 불러오기 모달 ── SCR-078
       │ 아래로 스크롤
       ▼
SCR-079 같은 예방 예산 화면 하단
       │ 다음
       ▼
SCR-080 재해예방업무처리 절차
```

## 5. 공통 셸과 재사용 컴포넌트

### 5.1 모든 컷에서 유지되는 셸

전 화면은 옅은 연두색 최상단 띠, 검정 GNB 바, 좌측 두 층 메뉴, 밀도 높은 본문 표, 하단 푸터라는 관공서 업무시스템 셸을 공유한다. 최상단에는 좌 `경영목표`와 `통합된 안전보건관리체계 확립으로 중대산업재해 ZERO 달성`, 우 `경영방침`과 `1. 안전문화 정착`이 있다. 헤더 로고는 `OO광역시 | 안전보건체계 통합관리시스템`이고, GNB 활성은 `의무이행(실적증빙)`이다. GNB의 전체 메뉴는 `이행현황`, `관리대상 현황`, `법 의무사항`, `의무이행(실적증빙)`, `이행점검 및 조치`, `기관장 예방활동`, `통계 및 사례`, `관리자`다.

좌측 첫 패널은 `의무사항(실적증빙)`이며 `사업장`, `공중이용시설 · 교통수단`, `원료·제조물` 중 선택된 트랙 앞에 `●`를 둔다. 옆의 스텝 아코디언은 번호 배지, 다크그린 활성 카드, 연녹색 확장 카드, 원형 `⌄`/`⌃` 토글을 쓴다. 공중이용시설·교통수단에는 ① 아래 다섯 항목, 원료·제조물에는 세 항목만 나온다. 본문 헤더는 `법 의무이행 조치` → 조문을 포함한 제목 → `사업장명 : 부서명 – 해당년도 : OOOO년` 흐름이다. 단, 원료·제조물은 원문상 `사업장명 – 해당년도 : OOOO년`으로 `부서명`이 빠진다. 푸터는 북부청사/남부청사 주소·전화와 저작권을 연회색 작은 글씨로 놓는다.

## 6. 육안 복제 포인트

### 6.1 색·여백·밀도

원본 PNG의 화면 크기는 2001×1127px이고, 넓은 검정 띠/여백과 밝은 표가 강하게 대비된다. 이미지 샘플에서 가장 뚜렷한 팔레트는 **옅은 연두 `#E2F0D9`**, 표/뷰어의 **아주 옅은 회색 `#F2F2F2`**, 흰 입력 배경과 중간 회색 테두리다. 다크그린 활성 카드와 버튼 테두리, 파란 외곽선 버튼/검색 버튼, 붉은 테두리 삭제 버튼을 조합한다. 정확한 CSS 토큰은 원문 디자인 파일로 확정해야 하지만, ① 연한 녹색 배경 ② 짙은 녹색 선택/강조 ③ 회색 표 헤더 ④ 파란 추가/검색 ⑤ 붉은 삭제의 위계는 반드시 유지해야 한다.

원본은 일반 웹 대시보드보다 훨씬 **고밀도**다. 표 헤더는 2줄 라벨까지 넣으며 행 높이는 낮고, 입력상자는 셀 안에서 최대 폭으로 붙는다. 페이지 최대 폭을 넓게 쓰고, 사이드바 두 칼럼은 본문과 명확히 구획한다. 여백을 지나치게 키우거나 카드형 UI로 바꾸면 관공서 원본의 인상이 사라진다. 화면에 크게 보이는 검은 영역은 GNB와 제목·본문 주변의 렌더링/마스킹 여부가 불명확한 면을 포함하므로, 서비스 배경색으로 그대로 확정하기 전에 원본 HWP 또는 발주처 확인이 필요하다.

### 6.2 표와 폼의 시각적 규칙

| 대상 | 복제 포인트 |
|---|---|
| 표 헤더 | 회색 배경, 진한 중앙 정렬 글자, 1px 회색 격자, `증빙자료` 아래에 작은 `※개당 10MB 이하`를 2줄로 둔다. SCR-075는 이 주석이 없다. |
| 입력셀 | 흰색 또는 매우 옅은 회색, 얇은 회색 테두리, 날짜는 작은 캘린더 아이콘 + `YYYY-MM-DD`, 숫자는 `0`을 중앙/우측에 보이게 한다. |
| 2단 헤더 | SCR-075의 `인적사항` 아래 `이름`/`소속(부서)`, SCR-072/074의 `점검주기` 아래 `주기`/`횟수`처럼 실제 `rowspan`/`colspan`으로 구성한다. |
| 첨부셀 | 파일명/`선택 파일 없음`은 왼쪽, 작은 `⤓`와 `🗑`은 오른쪽에 나란히, 그 아래 작은 사각 `+`를 둔다. SCR-075/077은 별도 `파일선택` 버튼을 포함한다. |
| 버튼 | `저장`은 회색 채움의 보수적 사각 버튼으로 표 우하단에 둔다. `항목 추가`, `개선 시정사항 추가`, `점검 항목 추가`, `계획수립 내용 검색 및 추가`는 흰 배경·파란 테두리이며 좌하단에 놓인다. |
| 스텝 네비게이션 | 본문 최하단에 좌/우로 넓게 벌리고 흰 배경·연두 테두리 카드 안에 `<`, `>`와 단계 라벨을 둔다. |
| 이미지 뷰어 | 넓은 연회색 직사각 패널, 좌상단 `이미지 뷰어`, 중앙 작은 이미지 플레이스홀더 아이콘이다. |
| 안내표 | 5개 열을 같은 폭으로 나누고, 상단은 회색 헤더, 본문은 작은 글씨의 불릿 나열이다. 세로 공간은 작지만 정보가 빽빽하다. |

### 6.3 사이드바·모달의 복제 포인트

사이드바의 첫 층은 약 280~320px 폭의 연녹색 판이며 `의무사항(실적증빙)`은 진한 녹색 헤더로 강조한다. 둘째 층은 약 250~260px 폭의 별도 스텝 열로, 번호 배지를 흰 원으로 쓰고 확장된 그룹의 하위 메뉴는 흰 카드에 연녹색 테두리를 준다. 활성된 그룹은 다크그린, 활성 하위 항목은 더 진한 연두로 표시한다. 아코디언은 현재 선택한 그룹만 열려 있는 모습이 기본이지만, 이미지에서는 ①의 하위 항목을 계속 노출한 상태가 많다.

`법령 검색`은 본문 우측 절반 이상을 덮는 밝은 대형 모달이다. 제목 아래 둥근 연회색 검색 바 안에 3개 작은 입력, 라벨, 파란 `🔍 검색` 버튼을 가로 배치하고, 결과는 작은 글씨의 6열 표로 촘촘히 보인다. 불러오기 모달은 폭이 더 넓고 모달 내 카드/테이블과 우하단 `불러오기` 버튼을 쓴다. SCR-074의 모달이 상단을 덮고 블록 B가 아래에 남는 모습은 페이지 전체를 교체하지 말고 현재 스크롤 좌표 위의 오버레이로 구현해야 한다.

## 7. 용인시 영업 시연 적용 판단

용인시 시연은 102개 설계 컷을 복제하는 과제가 아니라 **`dashboard → target → legal basis → obligation due date → evidence → inspection → correction → summary`**를 안정적으로 완주하는 시나리오여야 한다. 따라서 이 영역의 6개 실제 페이지 패턴을 새 경로로 증식하지 않고, 시연의 `/evidence`에서 선택된 의무항목의 메타데이터에 따라 상태를 바꾸는 방식이 적합하다. 법령 마스터는 읽기 전용으로 두고, 실적·증빙·점검 상태는 저장 가능한 업무 데이터로 둔다.

| 영역/기능 | 용인시 시연 판단 | 적용 방법 및 근거 |
|---|---|---|
| 공통 공공기관 셸 | **사용** | 옅은 녹색 목표 띠, 검정 GNB, 연녹색 LNB, 회색 검색패널, 고밀도 표는 공공 안전관리 시연의 신뢰감을 만든다. 용인시 로고·조직·주소·사용자 데이터로 치환한다. |

### 7.1 권장 데모 데이터/상태 모델

`duty_record`는 최소한 `target_id`, `duty_item_id`, `year`, `status`, `not_applicable`, `source_plan_record_id`, `submitted_at`을 가져야 한다. 표 행은 항목별 JSON만으로 무분별하게 섞기보다 `duty_record_detail`의 `schema_key`와 JSON payload, 또는 안전인력/예산/위험요인처럼 조회가 필요한 상세 테이블로 분리한다. 첨부는 `duty_evidence`에 파일 ID, 원 파일명, MIME 형식, 크기, 버전, 미리보기 가능 여부를 기록한다. 법령 선택은 원본 `law_id`와 법령명/조문/요약의 선택 당시 스냅샷을 모두 보존한다.

시연에서는 `미이행 → 보완필요 → 이행완료` 정정 흐름을 한 항목으로 보여 주고, `해당없음`은 별도 항목에만 적용한다. 새 증빙을 올려도 과거 증빙과 점검 의견이 사라지지 않아야 하며, `/summary`의 O/△/X/-와 완료율은 저장된 상태로부터 자동으로 갱신해야 한다.

## 9. 구현 우선순위

첫째, 공통 셸·사이드바·증빙 셀·단계 네비게이션을 구성한다. 둘째, `/evidence`의 메타데이터 기반 `InlineEditTable`에 6개 페이지 패턴의 스키마를 주입한다. 셋째, `해당없음`의 hide와 저장 상태, 증빙 보존, 이미지 뷰어를 완성한다. 넷째, 법령 검색과 계획 불러오기 모달을 데이터 계약이 확정된 호출부만 활성화한다. 마지막으로 계획→실적→점검→요약의 데이터 갱신을 연결한다. 이 순서는 원본 화면의 외형을 재현하면서도 용인시 영업 시연의 안정적인 폐루프를 보장한다.
