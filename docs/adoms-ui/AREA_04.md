# AREA 04 — 의무이행(실적증빙) · 중대산업재해 화면 분석

> **분석 범위:** `SCR-036`~`SCR-051` / 화면 컷 16장 / 실제 라우트·페이지 패턴 9종
> **대상 사용자:** `사업장, 부서` 담당자 로그인 예시인 `하천관리과` · `김안전`
> **분석 기준:** 입력 명세, 화면 인덱스, 공통 구현지침 및 원본 PNG 16장을 모두 직접 대조하였다. 이미지상 검은 가림 영역과 일부 상단 제목 잘림은 개인정보·GNB 가림 또는 스크롤 캡처에 따른 것이므로 제품 UI로 복제하지 않는다.[1] [2] [3]

## 1. 결론과 범위 판정

이 영역은 사업장 트랙의 **중대산업재해 의무 이행 실적을 증빙파일과 함께 직접 등록하는 업무 화면군**이다. 핵심은 목록 화면을 별도로 둔 CRUD가 아니라, 의무 항목마다 다른 스키마의 **인라인 편집 표**를 쓰고, 파일을 하단 `이미지 뷰어`에서 확인한 뒤 이전·다음 단계로 이동하는 방식이다. `저장`은 등록·수정 확정 기능이며, 이 범위에는 상신·결재·승인 UI가 없다.

16개 SCR 컷을 16개 라우트로 구현하면 안 된다. `SCR-038/039`, `SCR-040/041`, `SCR-042/043`, `SCR-044/045`, `SCR-046/047`, `SCR-048/049`는 각기 **한 라우트의 세로 스크롤 상단/하단**이다. `SCR-051`은 `SCR-050`에 체크한 상태를 설명하는 **주석 첨부 상태**이므로 별도 페이지가 아니다. 따라서 화면 캡처 기준 16개, 실제 업무 페이지는 9종, 재사용 가능한 폼 아키타입은 7종으로 판단한다.

| 구분 | 수 | 구성 |
|---|---:|---|
| 분석 화면 컷 | 16 | `SCR-036`~`SCR-051`의 원본 PNG 각 1장 |
| 실제 업무 라우트/페이지 패턴 | 9 | 방침, 전담조직, 관계자 배치, 위험성평가, 예산, 업무수행, 의견청취, 비상조치, 재발방지 |

| 상태 변형 관계 | 1쌍 | `050` 기본 ↔ `051` 무재해 체크 ON·재해 카드 딤/숨김 안내 |

## 3. 공통 진입 조건, 셸, 데이터 원칙

### 3.1 진입 조건과 공통 업무 문맥

`하천관리과`의 `김안전`처럼 `사업장, 부서` 범위가 부여된 담당자가 로그인한 뒤, GNB `의무이행(실적증빙)`에서 대상 `사업장`을 선택하고 좌측 의무 단계를 선택하면 진입한다. 데이터 조회 범위는 본인에게 지정된 관리대상이다. 모든 화면의 기본 레코드 문맥은 최소한 **관리대상, 의무항목, 해당연도, 등록 주체**로 식별해야 하며, 실제 화면에 표시되는 `대상`의 `본청` 또는 `사업장명 : 부서명 – 해당년도 : OOOO년`은 그 문맥을 사용자에게 알려 주는 표시값이다.[3]

모든 항목은 `저장` 전 입력 상태를 유지하고, 저장 시 해당 의무 실적과 첨부파일 연결을 갱신하는 방식으로 모델링한다. 사진·문서의 용량 표기는 `※개당 10MB 이하`로 공통이며, 한 셀의 `+`는 하나의 이행행을 추가하는 버튼이 아니라 **그 행에 증빙 첨부를 추가하는 버튼**이다. 행 단위 휴지통과 첨부 휴지통은 별도 의미로 구현해야 한다.

### 4.3 SCR-038 — `의무이행(실적증빙) – [사업장, 부서] 안전·보건관계자 배치` (상단)

| 항목 | 분석 |

| 사용자 액션 | 각 직급의 배치일을 고르고, `이름` 오른쪽의 `검색`으로 직원을 선택하며, 파일·비고를 입력하고 `저장`한다. 각 직급 셀의 `+`는 해당 직급 인원을 추가하고 증빙셀 `+`는 파일을 추가한다. `위탁` 배지는 해당 행의 위탁 상태 표시다. |

### 4.8 SCR-043 — `의무이행(실적증빙) – [사업장, 부서] 안전예산 편성·집행` (하단)

### 4.9 SCR-044 — `의무이행(실적증빙) – [사업장, 부서] 안전보건관계자 업무수행` (상단)

| 화면 내 제목·표 | `안전보건관계자 업무수행(중대재해법 시행령 제4조 제5호)`, `대상` `본청`. 2단 헤더는 `안전보건 관계자` / `평가 일자` / `인적사항`(`이름`, `소속(부서)`) / `증빙자료` / `비고`다. |

## 5. 실제 고유 페이지 패턴과 정보 구조

### 5.1 9개 라우트와 7개 구현 아키타입

`SCR-036`과 `SCR-037`은 별도 업무 라우트지만 기본 인라인 증빙표라는 같은 아키타입을 공유한다. `SCR-038/039`와 `SCR-044/045`도 사람/소속 2단 헤더 표라는 공통 아키타입이다. 이 구분을 따르면 화면별 JSX 복제가 아닌 `duty_item`별 스키마 구성으로 구현할 수 있다.

| 라우트/의무 | 실제 페이지 패턴 | 재사용 수준 | 특수 데이터 구조 |
|---|---|---|---|
| 안전·보건 목표 및 경영방침 설정 | 단일 기본 증빙표 | 기본 `InlineEditTable` | 단일 방침일·첨부·비고, 행 추가 없음 |
| 안전·보건·총괄·관리 전담 조직 설치 | 일반 이행 증빙표 | 위 기본 표에 내용 열 추가 | 일자·내용·첨부·비고 |
| 안전보건관계자 배치 | 인물 배치 매트릭스 + 하단 뷰어 | 인물 표 아키타입 | 직급별 인원, 직원검색, 위탁, readonly 관리감독자 |
| 유해·위험요인 확인 및 개선 절차 마련(위험성평가) | 범위일/평가유형 + 분류 이행표 | 분류형 표 | 위험성평가일·`정기평가`, 추가 행 |
| 안전예산 편성·집행 | 고정 예산 6행·금액 표 | 금액 셀·고정행 확장 | 항목별 편성액/집행액, 계획 연계 |
| 안전보건관계자 업무수행 | 인물 평가 매트릭스 + 하단 뷰어 | 배치 인물 표 파생 | 평가일·평가 증빙·2행 readonly 관리감독자 |
| 종사자 의견 청취 및 개선 | 이중 독립 표 | 분류형 표 2개 합성 | 섹션 A/B, 각 저장, 표 B 행 병합 |
| 비상조치계획 수립 및 이행 | 그룹 병합행 이행표 | 그룹형 표 | 사용자 추가 구분, 그룹별 다건 행, 계획 연계 |
| 재해 발생시 재발방지대책 수립 및 이행 | 반복 사고 카드 | 독립 카드형 | 무재해 플래그, 사고 다건, 3개 고정 문서행 |

### 5.2 권장 데이터 경계

공통 상위 엔터티는 `duty_record(target_id, duty_item_id, year, status)`와 다중 첨부 `duty_evidence`로 구성할 수 있다. 그러나 이 영역은 서로 다른 표를 같은 열에 억지로 저장하면 안 된다. 아래처럼 각 의무의 상세 JSON 또는 상세 테이블을 분리하고, 공통 증빙 엔터티는 `record_line_id`까지 연결하는 구조가 적합하다.

| 의무군 | 상위·상세 데이터 | 첨부의 귀속 |
|---|---|---|
| 방침/전담조직/위험성평가 | `duty_record` + 이행행(일자·내용·비고) | 각 이행행; 방침은 단일행 |
| 배치/업무수행 | 관계자행(직책, 직원 ID, 소속 표시, 위탁, 날짜, 비고, readonly 출처) | 각 관계자행 |
| 예산 | 예산항목행(고정코드, 편성액, 집행일, 집행내역, 집행액, 비고) + 계획 연결 | 각 예산항목행 |
| 의견청취/비상조치 | 섹션·그룹과 하위 이행행 | 각 이행행 |
| 재발방지 | `no_accident_history` + 사고카드(사고명, 발생일) + 고정 문서행 | 사고카드의 문서행 |

## 7. 육안 복제 포인트

원본은 약 2001px 폭의 데스크톱 캡처이며 정보 밀도가 높다. 반응형 모바일형 카드로 바꾸면 이 명세의 시각적 정체성이 사라진다. 넓은 본문 표와 고정성 사이드바를 우선 재현하고, 작은 화면은 가로 스크롤 또는 별도 반응형 정책을 발주처와 확인해야 한다.

| 항목 | 관찰된 복제 포인트 |
|---|---|
| 색 체계 | 최상단과 대상 사이드바는 매우 연한 녹색, 그룹 헤더는 진녹색, 선택 스텝은 연녹색, 표는 백색 바탕과 차가운 연회색 헤더다. 녹색 테두리 흰색 버튼이 이전/다음이고, 일반 `저장`은 회색, 계획 검색·`재해 추가`는 청색 테두리, 카드 `삭제`는 적색 테두리다. 원본에 색상 토큰값은 없으므로 비슷한 값부터 적용하고 픽셀 대조로 조정한다. |
| 밀도·정렬 | 좌측은 대상 패널과 스텝 패널의 2단 구조이고, 본문은 남은 폭을 거의 모두 쓰는 고밀도 표다. 셀 사이 1px 회색 선, 좁은 패딩, 작은 입력 높이, 파일명 긴 한 줄 텍스트가 특징이다. `SCR-046`의 두 표와 `SCR-050`의 카드도 전체 폭을 사용한다. |
| 표 헤더 | 회색 헤더에 굵은 가운데 정렬 한글, `증빙자료`/`※개당 10MB 이하`는 2줄이다. 038/044는 `인적사항` 병합 상단 헤더 아래에 `이름`, `소속(부서)`가 놓이는 2단 헤더를 정확히 구현한다. |
| 입력 위젯 | 날짜 입력은 좌측 작은 달력 아이콘을 포함한다. 파일은 회색 파일명 박스, 사각 `파일선택`, 사각 다운로드 아이콘, 사각 휴지통 아이콘의 연속 배치다. `+`는 아주 작은 사각 버튼으로 셀의 하단 왼쪽에 배치된다. |
| 사이드바 | `①`~`④` 흰 원형 배지, 우측 원형 `∨`/`∧`, 흰 스텝 버튼의 연녹색 테두리, 활성의 배경 강조가 중요하다. 긴 단계명은 원본처럼 2줄을 허용한다. |
| 뷰어·도움말 | 뷰어는 매우 큰 연회색 패널이며 `이미지 뷰어` 굵은 제목이 좌상단, 비어 있으면 정중앙 회색 산 모양 아이콘이다. 도움말은 별도 연회색 띠/박스에 굵은 제목과 짧은 줄글이다. 036에서는 문서를 실제 세로 종이 형태로 작게 중앙 렌더한다. |
| 상태 표현 | `위탁`은 체크 아이콘과 작은 회색 배지, readonly 셀은 중간 회색 채움·희미한 글자다. SCR-051의 회색 오버레이는 기능 설명 상태이고 분홍 말풍선·빨간 화살표는 운영 UI에 넣지 않는다. |
| 캡처 가림 처리 | 검은 가로 띠, 가려진 GNB/타이틀, 일부 잘린 `대상` 배지는 데이터 마스킹 또는 스크롤 결과다. 검은 공백을 페이지 디자인으로 모사하지 말고, 정상 Header와 문서 흐름을 구현한다. |

## 8. 용인시 영업 시연 적용 판단

판단 원칙은 **법적 의무 라벨은 원문을 유지**하고, `OO광역시`, `하천관리과`, `김안전`, 주소·전화, 샘플 `test`와 같은 조직·더미 데이터만 승인된 용인시 시연 데이터로 치환하는 것이다. 아래의 “숨김”은 기능 삭제가 아니라 첫 시연 동선에서 감추고 요청 시 노출한다는 뜻이다.

| 화면/상태 | 판단 | 용인시 영업 시연 적용 | 상태 재사용 |
|---|---|---|---|
| SCR-036 | **사용** | 시작 화면으로 적합하다. `대구광역시 안전보건 경영방침.PDF` 대신 용인시 시연용 방침 PDF를 넣어 증빙 업로드→미리보기 가치를 즉시 보인다. | 파일 미선택/선택 미리보기만 필요 |

| SCR-051 | **숨김 (운영 UI), 상태재사용** | 말풍선/화살표는 화면 명세 설명용이므로 고객 화면에는 숨긴다. 대신 체크 ON으로 사고 카드가 사라지고 `저장`만 가능한 상태를 직접 시연한다. | SCR-050의 `noAccidentHistory=true` 상태 |
| 그룹 ③·④ | **숨김/미구현 범위 표시** | 이 분석 범위에는 그룹 ③ `개선·시정 등을 명한 사항 이행`, ④ `관계 법령상 의무이행`의 상세 화면이 없다. 좌측 아코디언은 보이되 해당 기능은 범위 밖 또는 후속 화면으로 명시한다. | 동일 사이드바만 재사용 |

용인시 영업 시연의 **권장 대표 동선**은 `SCR-036 → SCR-038/039 → SCR-042/043 → SCR-046/047 → SCR-050 기본/무재해 상태`다. 이 순서는 방침 증빙, 인력 배치, 예산 집행, 의견 반영, 사고 발생/무발생이라는 업무 가치를 가장 짧게 설명한다. 원본의 하단 `N단계` 버튼은 라벨 불일치가 있으므로 데모에서는 좌측 스텝 클릭 또는 별도 확정 네비게이션으로 이동하고, 원문 라벨은 디자인 검증용으로 유지한다.

## 10. 구현 인수 기준

다음 기준을 충족하면 이 영역의 시각·업무 구현이 명세에 부합한다. 첫째, `SCR-038/039` 등 여섯 쌍이 각각 하나의 URL에서 자연스럽게 스크롤되고, `SCR-051`은 URL 없이 `SCR-050`의 체크 상태로 재현되어야 한다. 둘째, 모든 표에는 원문 컬럼 라벨과 `※개당 10MB 이하`가 나타나고, 첨부 행 추가와 이행행 추가가 서로 섞이지 않아야 한다. 셋째, 인물 표의 2단 헤더·`검색`·`위탁`·readonly 행, 예산 표의 6개 고정항목과 두 금액열, 의견청취의 두 독립 저장, 재발방지의 다건 카드·무재해 토글이 각각 동작해야 한다.

넷째, 좌측 2단 메뉴의 활성 색과 `대상` 선택 상태, 큰 빈 `이미지 뷰어`, 증빙예시, 녹색 테두리 단계 버튼과 회색/청색/적색 목적별 버튼을 유지해야 한다. 다섯째, 단계 버튼의 보이는 문구는 원문을 유지하되 데이터 모델의 route는 확정된 별도 매핑을 따르며, 확인이 끝나지 않은 사항은 동작을 임의로 단정하지 않아야 한다.
