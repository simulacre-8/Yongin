# 의무이행 기록모델 근거

**검토일:** 2026-09-07

시설물안전법 관련 의무이행은 단일한 “완료” 사건보다 **업무구분**, **기록구분**, **실제 조치이행 기간**, **문서 등록시각**, **첨부 증빙**을 분리해 보존하는 편이 적절하다.

## 법령·제도 근거

국토교통부의 시설물안전 관리제도 설명은 시설물별 안전 및 유지관리계획의 수립·시행, 안전점검, 정밀안전진단, 결과 통보·실적관리, 긴급 안전조치를 서로 구분된 업무로 설명한다. 관리계획에는 안전점검·정밀안전진단, 비용·예산, 긴급조치체계, 설계도서 수집·보존 및 전년도 이행실적 등이 포함된다.[1]

생활법령정보는 시설물안전법상 안전점검을 정기안전점검·정밀안전점검·긴급안전점검으로 구분하고, 정밀안전진단을 별도 행위로 설명한다. 현행법 기준 시행일은 2026-08-28로 안내한다.[2]

따라서 데모의 업무구분은 사용자 승인안대로 `계획`, `계약`, `정밀안전진단`, `안전점검`, `기타`로 두고, 사건의 기록구분은 `변경`, `이행`, `시정`으로 별도 관리한다. “계약”은 법률상의 점검 종류가 아니라 도급·용역·위탁을 통한 수행에 필요한 운영 문서 분류이므로 **업무 문서 분류**로 명시한다.

## 첨부 양식 근거

사용자 첨부 PDF `시설물의안전및유지관리에관한조치이행양식.pdf`의 서식 1은 `시설물 안전관리 조치 및 증빙자료 양식`으로, 책임자 소속·성명, 조치일자·기록, 도급·용역·위탁업체의 업체명·사업자번호·대표이사·연락처·참여기술자, 처리 세부내용과 관련 사진 설명을 한 문서로 관리한다.

이를 반영해 화면의 조치내용은 **첨부문서 핵심내용 요약**으로 정의하고, 자유 비고 입력은 제거한다. 업무구분별 빈 Word 양식 1~5를 제공하며 실제 작성·첨부 문서의 원본 파일명과 등록시각은 증빙 메타데이터로 보존한다. 양식 파일은 저장소의 `docs/compliance-action-forms/`에서 버전 관리하고 GitHub 원본 URL로 제공한다.

## 시간·담당자 계약

- `action_start_date`, `action_end_date`: 실제 조치이행 기간
- `occurred_at`: 브라우저가 전달한 업무 사건 발생시각
- `created_at`: DB 등록시각
- `evidence.uploaded_at`: 파일 등록시각
- `actor_employee_no`, `actor_org_name`, `actor_display_name`: 등록 당시 시연 프로필 스냅숏
- `work_origin`, `delegated_at`: 내 업무 런타임에서 위임요청 후 실제 재배정된 경우에만 파생하는 위임업무 구분과 재배정 시각. 요청 대기 중이면 본래업무로 유지한다.

후행 백필에서도 과거 업무시각은 `occurred_at`에만 보존하고 `created_at`은 실제 삽입 시점의 DB 기본값을 사용한다. 화면과 CSV는 같은 `created_at`을 등록일시와 DB기록시각으로 중복 표시하지 않는다.

현재 로그인은 Supabase Auth 개인 신원 인증이 아닌 공유 시연 프로필이다. 직원번호는 실제 인사번호가 아니라 프로필 UUID에서 파생한 `DEMO-…` 표기이며 운영 전 인사 마스터와 Auth 사용자로 교체해야 한다.

현재 위임업무 판정은 **위임요청 이후 실제 재배정 사건 존재 여부**를 사용하는 시연 규칙이다. 요청 대상과 최종 재배정 대상의 승인 관계까지 증명하는 운영 권한모델은 아니며, 실운영에서는 위임 승인·반려·인수 사건과 Auth 신원을 별도로 연결해야 한다.
