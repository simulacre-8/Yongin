## 원천 파일 판독

의무풀 파일은 물리적으로 헤더 포함 5,057줄이다. `anchor_text`의 따옴표 안에 줄바꿈이 포함되어 있어 물리 줄 수는 의무 수가 아니다. 표준 CSV 파서로 읽은 논리 레코드는 3,688건이며 이 값을 원격 적재 기준으로 사용했다.

세 CSV의 SHA-256, 논리 행 수, 키 검증 결과는 `docs/YONGIN_CORE_DATA_VERIFICATION.md`에 기록했다. 재현 스크립트 `scripts/build-yongin-core-data.py`는 수량, 중복, 매핑 완전성, 제목·법령·조문 경로 충돌을 모두 검사한 뒤 전체 의무풀 시드를 생성한다.

## 업무 폐쇄루프

`007_facility_workflow_bridge.sql`은 읽기 전용 시설 참조와 쓰기 업무 계층을 연결한다. `target.target_ref`와 `target_obligation.obl_id`가 원천 ID를 유지한다. `v_facility_workflow`는 `target_ref + obl_id + period_key`를 기준으로 기한, 이행, 증빙 연결점, 점검 결과를 제공한다.

대표 브라우저 검증은 `고기상수도(FMS:WS2013-0000051)`와 `긴급안전점검의 실시(OBL-0002590)`로 수행했다. 실적 저장 성공 토스트를 확인한 후 원격 뷰에서 같은 `target_obligation_id`, `period_key=2026-H2`, `compliance_status=NONE`, `action_date=2026-09-05`를 재조회했다. 이 레코드는 시연에서 결과가 실제로 남는 것을 보여주기 위해 유지한다.

`facility-workflow-smoke.ts`는 테스트 전의 이행시기 값을 기억한다. 이후 이행시기 업데이트, `compliance_record` upsert, 비공개 Storage 업로드, `evidence` 메타데이터 저장, `inspection_scope`, `inspection_result`, 총괄 뷰 재조회를 수행한다. 마지막에는 테스트 레코드와 파일을 삭제하고 이행시기를 원복한다.

페이지마다 반복되던 공통 고정 LNB는 제거했다. 홈은 본문 내부 220px 로컬 의무 분류 패널을 사용하고, 증빙처럼 의무 단계 선택이 필요한 화면만 페이지 전용 로컬 탐색을 유지한다. 관리대상·의무 체크리스트·실적증빙·점검·총괄표는 `selectedTargetId`를 공유한다.

2026-09-07 UI 검수에서는 홈의 `중대산업재해` 하위에 `사업·사업장 14`를 추가하고, 그 다음에 `중대시민재해`의 `공중이용시설·공중교통수단 13`과 `원료·제조물 9`를 같은 단계의 선택 항목으로 배치했다. 홈과 의무이행의 로컬 탐색은 제목·그룹·선택 항목의 폰트 위계를 통일하고 배경색·왼쪽 인셋 표시가 160ms로 전환되는 하나의 선택 효과를 사용한다. 의무이행에서 두 번째 의무를 선택했을 때 첫 번째 의무의 선택 보더가 즉시 해제되는 것을 브라우저에서 확인했다.

의무이행 표의 증빙자료 열은 업무 입력 필드 오른쪽 끝으로 이동했다. 설정에는 대상 프로필 바로 아래 공식 조직도 카드가 추가되어 Supabase의 활성 조직 792건을 검색하고 상위조직별 부서·팀을 조회한다. 내 업무의 `첨부파일을 저장하시겠습니까?` 모달은 흰색 콘텐츠 표면과 남색 텍스트로 렌더링되며 취소 후 파일 입력이 0건으로 비워져 파일이나 메타데이터가 저장되지 않는 것을 확인했다.

의무 체크리스트는 검색조건 선택을 제거하고 시설물명·주소·소속을 한 입력에서 검색한다. 브라우저에서 `경전철 관리부서`를 입력해 용인경전철 한 건만 조회되는 것을 확인했다. 홈의 공중이용시설·공중교통수단 13건, 관리대상 공중이용시설 150건, 의무 체크리스트 151건에는 각각 현재 결과 CSV 버튼이 표시된다.

고기상수도 의무이행 CSV는 헤더 1행과 적용 의무 31행, 총 24개 열로 생성됐다. 관리대상·법령·조항·주기·증빙요건·상태·조치시각·점검·첨부 파일명을 포함하며 UTF-8 BOM과 CSV 수식 주입 방어를 적용한다. 다운로드 직후 `demo_compliance_export_event`에서 파일명, 31건, 역할 `경영책임자`, 브라우저 발생시각, DB 기록시각을 재조회했다.

한글 PDF 증빙을 미이행 의무에 저장했을 때 상단 집계가 `이행완료 0 → 1`, `미이행 31 → 30`으로 즉시 바뀌었다. 하단에는 기존 `증빙자료 예시` 대신 시정조치 최초 등록·변경 이력과 증빙 메타데이터가 표시된다. 이 검수에서 감사이력의 식별자가 `compliance_id`가 아니라 `target_obligation_id`임을 확인해 조회 API를 수정했다. 브라우저 검증용 파일·상태·감사이력은 기준값으로 복원했고 CSV 다운로드 로그 한 건만 시연 로그로 유지했다.

독립 코드 검토 후 실제 시설 workflow 의무에서는 `이행 내역 추가`를 숨겨 한 의무·한 시정조치 행만 저장한다. 저장된 증빙은 서버 삭제·감사 절차가 마련되기 전까지 삭제 버튼을 표시하지 않고 새로 선택한 미저장 파일만 취소할 수 있다. 증빙 저장 API는 Storage 업로드를 먼저 완료한 뒤 이행상태와 메타데이터를 기록하며, 후속 단계가 실패하면 새 객체·메타데이터와 변경된 이행상태를 보상 복구한다.

실제 workflow 행에서는 한 번에 새 증빙 한 개만 선택한다. 다른 파일을 다시 선택하면 아직 저장하지 않은 선택만 교체하며, 저장 성공 직후 로컬 `File`을 서버 증빙 메타데이터로 치환해 같은 파일의 즉시 중복 재저장을 막는다.

## 홈 의무 상세와 기능 IA

현재 검수용 GNB는 `홈 → 관리대상 → 의무 체크리스트 → 의무이행 → 내 업무 → 설정` 순서다. `/dashboard`의 기존 이행현황 대시보드는 실제 Supabase `내 업무`로 교체했다. 역할별 조직 범위, 20건 페이지 목록, 공식 조직도 수동배정, 수락, 상태 변경, 위임요청과 필수 근거파일, 완료, 완료 확인, 확인형 첨부, 이력, 선택 CSV를 제공한다. `이행점검`은 GNB에서 숨기고 기존 라우트는 후속 업무 흐름 검수용으로 유지한다.

설정 화면으로 대상 프로필 사실값을 이동했다. 브라우저에서 120명·39,872㎡·기준일 2026-09-05를 저장한 뒤, 원격 `target_applicability`의 `RUL-000840`, `RUL-000841`, `RUL-000900`, `RUL-000901` 네 행에서 같은 입력 스냅숏과 기록시각을 재조회했다. 기본 `/`는 홈이며 적용범위 판정의 정식 경로는 `/settings/applicability`다. 적용범위 화면에서는 L1/L2/L3 시각화와 사실값 입력 영역을 제거하고 `조건 충족`, `추가 확인`, `원천 검수 필요`를 같은 규격의 가로 카드로 표시하며 선택 의무의 근거·판정 경로는 하단 전체 폭에서 확인한다.

홈의 중대산업재해 선택 시 14개 항목을 LNB 아래로 다시 펼치지 않는다. 대신 오른쪽 목록의 각 의무 아래에 `article_title`과 `detail_ko`를 원문 그대로 분리한 최대 3개 세부 점검사항을 번호·들여쓰기로 표시한다. 의무 행을 선택하면 `v_facility_workflow`에서 같은 `obl_id`의 점검 상태 우선, 이행 상태 보조 정책으로 O/△/X/- 건수와 이행률을 집계한다.

현재 원격 DB에는 용인시 공식 조직 계층이 구축되어 `기획조정실`, `안전정책관 / 중대재해예방팀`, `재난대응담당관 / 재난대응팀`, `교통정책국 / 도시철도과 / 경전철관리팀`, `상수도사업소 / 수도시설과 / 수도시설팀`을 실제 경로로 조회할 수 있다. 내 업무 초기상태는 승인된 시연 방침에 따라 2,235건을 시연 내부 소관규칙으로 자동배정하고 656건을 수동 선택 대기로 둔다. 자동배정은 법적 소관 판정이 아니며 화면과 문서에서 같은 한계를 표시한다.

브라우저에서는 실·국 점검자 역할을 선택했을 때 교통정책국 범위의 용인경전철 5건을 조회했다. `운전업무종사자 등의 관리`를 수락하고 완료한 뒤 완료 확인 메모를 입력했다. 카드에서 수락시각, 완료시각, 확인시각, 확인자 `이점검`을 각각 확인했다. 확장 이력에서는 `ACCEPTED`, `COMPLETED`, `CONFIRMED`가 별도 사건으로 표시됐고 각 사건의 발생시각과 기록시각을 확인했다. 헤더 초기화 확인 모달로 정리한 뒤 원격 DB는 업무 2,891건, 자동 2,235건, 수동 656건, 확인 0건, 첨부 0건, 위임 0건으로 복구됐다. 브라우저 콘솔 오류는 없었다.

이번 최종 체크포인트에서는 사용자가 직접 만든 내 업무 시연값을 보존했다. 현재 업무 2,891건 중 자동 2,234건·수동 657건이며 첨부 3건·위임요청 2건이 존재한다. `smoke:my-work`는 깨끗한 기준상태가 아니면 초기화를 거부하도록 설계되어 실제로 중단됐고, 이 안전장치를 우회하거나 헤더 초기화를 실행하지 않았다. 내 업무를 변경하지 않는 `smoke:my-work-storage`와 나머지 비파괴 스모크는 통과했다.

첨부 버튼은 파일 선택 후 파일명과 크기를 보여주는 확인 모달을 표시한다. 브라우저에서 확인을 취소한 뒤 `demo_work_attachment`가 0건으로 유지됨을 원격 조회했다. RPC 스모크에서는 최초 `assigned_at`이 두 번의 재배정 뒤에도 유지되고 최종 재배정만 `reassigned_at`에 기록됨을 확인했다. 수락 전 상태 변경·위임과 완료 후 재배정·상태 변경·위임은 모두 거부됐다.

한글 파일명에서 발생한 Supabase Storage `Invalid key`는 객체 경로에 원본 파일명을 포함한 것이 원인이었다. 객체 키를 `demo/my-work/{workItemId}/{UUID}.{extension}`의 ASCII 전용 형식으로 변경하고 원본명은 첨부 메타데이터와 다운로드 이름에만 보존한다. `인하대_과학영재센터_과제b_3A이민후_20260214.pdf` 표본을 ASCII 경로로 실제 업로드·다운로드하고 즉시 삭제하는 `pnpm smoke:my-work-storage`가 통과했다. 화면은 10MB 이하의 HWP, TXT, PNG, JPG/JPEG, DOC/DOCX, PDF만 선택할 수 있도록 안내하고 검증한다.

클린 설치 순서는 `012`~`018` 스키마·함수 마이그레이션을 먼저 적용하고, 시설 workflow와 공식 조직도 시드가 끝난 뒤 `seed_my_work_runtime.sql`을 마지막에 실행하도록 분리했다. 정적 회귀 테스트는 `012`가 특정 조직 FK 데이터나 즉시 업무 생성에 의존하지 않는지와 README의 후행 seed 순서를 검사한다.

Supabase Advisor 재검사에서 새 내 업무 테이블의 미인덱스 FK 권고는 모두 해소됐다. 익명 `SECURITY DEFINER` RPC 경고는 공유 영업 시연에서 의도한 접근 방식이며 운영 보안으로 간주하지 않는다. 실제 운영 전에는 익명 실행 권한을 회수하고 Supabase Auth 사용자·조직 범위 RLS로 교체해야 한다.[5]

## 용인시 공식 조직도

용인시 공식 조직도 3개 화면과 공개 부서 상세를 파싱해 `ref_yongin_org_snapshot`, `ref_yongin_org_unit`, `v_yongin_org_tree`에 적재했다. 활성 조직은 총 792건이며 구조 단위 202건과 공개 `…팀장` 직위에서 파생한 팀 590건으로 구성된다. 시청 2실·13국·66과, 직속기관 4기관·9과, 사업소 5개·14과, 3개 구청·38과·39읍면동 구조 수량은 공식 표기와 일치한다.

팀 합계는 공식 조직도 헤더와 공개 담당자 목록의 스냅숏 범위가 달라 분리 보존한다. 개인 이름은 적재하지 않았고 `부팀장`을 `부팀`으로 오인하던 파싱 규칙을 제거한 후 원격 `부팀` 활성 행 0건을 확인했다. 상세 기준과 재현 절차는 `docs/YONGIN_ORG_IMPORT.md`에 기록했다.

## 법령 원문 팝업

의무이행 표의 법령 참조 필드는 `ref_obligation.doc_id/unit_path/article_no`와 `ref_legal_document.document_title/norm_form`에서 조회한다. 화면에는 내부 경로 `a13/p1` 대신 `제13조 제1항`을, 구분에는 `법률/시행령/시행규칙`을 표시한다. 고기상수도 31개 의무는 문서 ID·조문 경로·조문 번호가 모두 31/31건 존재한다.

Netlify 빌드는 `VITE_SUPABASE_URL`과 `VITE_SUPABASE_PUBLISHABLE_KEY`가 없으면 실패하도록 보호했다. 성공한 산출물은 `/build-info.json`과 `/manifest.json`을 생성한다. F12 Network에 Supabase 요청 자체가 없으면 RLS 거부가 아니라 배포 번들 환경변수 누락으로 판정하며, RLS 거부는 Supabase 요청의 401/403 응답으로 구분한다.

`009_legal_source_popup.sql`은 `ref_legal_document`와 `ref_obligation_legal_source`를 추가한다. 용인시청 로컬 의무 `OBL-01`~`OBL-10` 모두 ADOMS 정식 `unit_id`에 연결했다. 의무 마스터가 없던 비상대피훈련 `OBL-07`은 `UNIT-0011597`(재난 및 안전관리 기본법 제35조 제1항)에 직접 연결했고, 관계 법령상 의무이행 `OBL-10`은 시설물안전법 제6조 제1항과 제11조 제1항 두 원문을 순서대로 연결했다.

팝업은 법령명·한글 조문·원문을 표시하고 내부 코드 경로는 숨긴다. 날짜는 **법령 최근 개정일**, **현행법령 시행일**, **해당 조문 효력일**을 분리 표시한다. 앞의 두 값은 2026-09-06 국가법령정보센터 현행법령 조회 스냅숏이며, 원문과 조문 효력일은 ADOMS 사실층 기준이다.

브라우저에서 비상대피훈련 복사 payload 474자를 검사해 의무명, 최근 개정일, 시행일, 본문을 모두 확인했다. 인쇄 버튼은 제어된 `window.print` 스텁에서 1회 호출됐으며, 인쇄 CSS는 앱 외곽과 액션 버튼을 숨기고 팝업 본문만 A4로 출력하도록 구성했다. 다중 조문·복사·인쇄 전환 후 브라우저 콘솔 오류는 없었다.

## 상태 집계 정책

총괄표는 점검결과가 있으면 `inspection_result.status`를 우선한다. 점검결과가 없고 이행기록이 있으면 `compliance_record.status`를 사용한다. 두 값이 모두 없으면 `해당없음(-)`으로 표시한다. 이행률 분모에서는 `해당없음`을 제외한다.

## 남은 범위

전체 의무풀, 시설별 매핑, 공식 조직 계층과 초기화 가능한 내 업무 런타임은 원격 DB에 구축됐다. 남은 주요 갭은 승인된 실운영 조직–의무 소관표, 직원 인사 마스터, 실제 Supabase Auth 사용자 연결, 조직 범위 RLS, 도급 계약원장 상세, 위임 승인·반려·잠금, 메시지·조치지시 이력이다. 경전철과 도급 2건은 실제 원천을 받을 때까지 `DEMO_VIRTUAL` 표시를 유지한다.
