# 용인시 데모 디자인 재구성 브리프

**기준일:** 2026-09-06

**공식 참고:** https://www.yongin.go.kr/index.do

**Git 디자인 기준선:** `c51089d`

## 방향

현재 8개 라우트의 메뉴 뎁스, 시연 필드, Supabase 연결과 저장 동작은 보존한다. 시각 체계는 클라이언트가 선호한 초기 용인시 브랜드 디자인으로 되돌린다. 공식 홈페이지의 넓은 여백, 밝은 카드, 부드러운 분홍·아이보리 표면, 마젠타·퍼플·청록 포인트, 둥근 컨테이너와 얕은 그림자를 적용한다. 검정 GNB는 유지한다.

## 타이포그래피

영문·숫자는 `Inter`, 한글은 `Noto Sans KR` fallback을 사용한다. 기능 화면의 크기는 12/14/16/20/28px 다섯 단계 이내로 제한한다. 기본 본문과 표는 14px, 보조 정보는 12px, 메뉴와 입력은 14px, 섹션 제목은 16px, 페이지 제목은 28px를 기본으로 한다. 강조는 크기보다 `#A93193`·`#DF3355` 색상과 굵기 차이로 표현한다.

## 보존 조건

- 적용범위 판정은 첫 화면으로 유지한다.
- 현재 GNB·LNB 메뉴 순서와 화면 내 필드 위치는 시연자가 익숙한 범위에서 유지한다.
- 관리대상에는 FMS 시설 150건, 공중교통수단 1건, 도급 2건을 유지한다.
- 실제 Supabase 조회·판정 저장은 제거하거나 목업으로 되돌리지 않는다.
- 증빙·점검 등 로컬 저장만 사용하는 화면은 디자인 완료와 별도로 DB 연결 갭으로 보고한다.

## 적용 및 검증

공통 셸은 검정 GNB와 기존 메뉴 순서를 유지하면서 LNB와 본문을 연분홍·아이보리의 밝은 면, 흰 카드, 얕은 그림자로 다시 구성했다. 화면별 하드코딩 색보다 전역 토큰의 우선순위를 높여 검색 패널, 표, 입력폼, 저장 버튼의 스타일을 통일했다.

1600×900에서 `/`, `/dashboard`, `/targets`, `/laws`, `/obligations`, `/evidence`, `/inspection`, `/summary`를 전체 페이지로 검증했다. 적용범위 3단 워크벤치, 이행현황 3열, 150건 시설 목록, 법령 검색표, 의무 이행시기 표, 증빙 입력표, 점검 취합 2열, 점검 총괄표의 기존 위치와 기능 필드는 유지됐다. 총괄표 상태면은 이행완료=청록, 보완필요=노랑, 미이행=주황, 해당없음=흰색으로 구분한다.

## 최종 시각 점검

Inter·Noto Sans KR 로드와 상태색 수정 후 1600×900에서 적용범위·이행현황·점검 총괄표를 다시 확인했다. 검정 GNB와 기존 메뉴 순서, 고정 LNB, 입력·표의 필드 위치는 유지됐다. 본문은 밝은 연분홍·아이보리 배경과 흰 카드로 통일됐으며, 주 동작은 마젠타·퍼플, 이행완료는 청록, 보완필요는 노랑, 미이행은 주황으로 구분된다. 상단 연결 문구는 전체 업무저장으로 오인되지 않도록 `Supabase 기준정보 연결`로 정정했다. WebDev 상태는 실행 중, 의존성 정상, LSP 오류 0건, TypeScript 오류 0건으로 확인됐다.
