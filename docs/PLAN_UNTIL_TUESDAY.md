# 화요일까지 법령 DB 시연 구현 시간대별 일정

**기준 시각:** 2026-09-05 토요일 21:00  
**기준 시간대:** 한국 표준시(KST)  
**기능 완료 시점:** 2026-09-07 월요일 23:00  
**최종 시연 준비 완료:** 2026-09-08 화요일 12:00

## 1. 일정 운영 원칙

이번 일정은 **월요일 밤에 기능을 동결하고 화요일에는 신규 개발을 하지 않는 방식**으로 구성한다. 시연 시간이 화요일 오전이더라도 월요일 23:00 버전을 사용할 수 있어야 한다.

개발 범위는 핵심 법령 50~150개를 조회 가능한 형태로 축소 적재하되, 실제 자동 판정에는 수동 검수된 8~12개 규칙만 사용한다. 대표 대상 1개는 전체 입력·보완 플로우를 수행한다. 비교용 대상 2개는 총괄표와 이행률 표시를 위해 시드 데이터로 제공한다.

| 구분 | 이번 완료 범위 | 제외 범위 |
|---|---|---|
| 법령 | 핵심 50~150개, 관련 조문, 적용조건, 의무 연결 | 전체 195개 법령과 72만여 행의 전건 적재 |
| 판정 | 검수 완료 규칙 8~12개 | 미검수 규칙 전체 자동 실행 |
| 역할 | 담당자, 실·국 점검자, 경영책임자 | 정식 회원가입·비밀번호 찾기·조직 인사 연동 |
| 업무 | 대상 판정, 의무 저장, 증빙, 점검, 보완, 집계 | 전자결재, 엑셀 다운로드, 관리자 전체 기능 |
| UI | 공통 셸과 핵심 6~7개 화면 | 102개 화면 전체 구현 |

### 토요일 종료 산출물

토요일 밤에는 화면이 예쁘게 보일 필요가 없다. **마이그레이션 재실행이 가능하고 실제 데이터 한 건이 저장되는 상태**면 완료다.

### 일요일 종료 산출물

일요일 23:00에는 **대표 대상의 조건을 입력하면 검수된 법령과 의무가 도출되고, 이행시기를 저장한 뒤 새로고침해도 값이 남아야 한다.** 이 상태가 안 되면 월요일 UI 세부 작업을 시작하지 않는다.

## 5. 9월 7일 월요일 — 증빙·점검·집계 완성과 기능 동결

| 시간 | 작업 | 구체적 완료 조건 |
|---|---|---|
| 09:00~09:30 | **일요일 결과 스모크 테스트** | 초기화 → 조건 입력 → 판정 → 의무 저장을 처음부터 다시 수행한다. 오전 첫 30분에 전일 회귀 오류를 찾는다. |
| 09:30~10:30 | **의무이행 기록 화면** | 의무별 조치일자, 상태, 비고를 저장한다. 상태 문자열은 `이행완료`, `보완필요`, `미이행`, `해당없음`으로 고정한다. |
| 10:30~11:30 | **증빙 업로드 백엔드** | 실제 파일을 비공개 Storage에 업로드하고 파일 메타데이터를 `evidence`에 저장한다. 파일 크기와 소유 기록을 남긴다. |
| 11:30~12:00 | **증빙 다운로드·삭제** | 등록한 파일의 다운로드와 삭제가 동작한다. 미리보기는 여유가 있을 때만 구현한다. |

| 13:00~14:00 | **의무이행 UI 완성** | 법령명·조문·법령내용은 읽기 전용으로, 조치일자·증빙·비고는 편집 가능하게 구성한다. |
| 14:00~15:00 | **점검 회차·범위 생성** | 비교 대상 3개와 의무 8~12개를 포함하는 점검 회차를 생성한다. 선택 대상과 항목이 후속 화면 범위를 결정한다. |
| 15:00~16:00 | **점검 화면 구현** | 점검자는 상태와 점검내용만 수정한다. 대상, 이행일자, 증빙은 읽기 전용으로 표시한다. |

| 16:40~17:30 | **담당자 보완 제출** | 기존 증빙 이력을 유지하면서 새 증빙을 추가하고 재제출할 수 있다. 최신 제출과 이전 이력을 구분한다. |
| 17:30~18:00 | **재점검 완료** | 점검자가 동일 항목을 `이행완료`로 바꾸고 변경 전후 상태와 시각이 남는다. |

| 19:00~20:00 | **총괄표·이행률 계산** | O/△/X/- 행렬, 항목별 건수, 대상별 이행률을 저장된 점검 결과에서 계산한다. `해당없음`은 모수에서 제외한다. |
| 20:00~20:40 | **대시보드 최소 위젯** | 대상 수, 이행완료·보완필요·미이행 건수, 전체 이행률만 집계 뷰에서 표시한다. |
| 20:40~21:20 | **역할 전환·접근범위 검증** | 담당자, 실·국 점검자, 경영책임자 관점에서 노출 화면과 편집 가능 필드를 확인한다. 데모용 단순화가 있으면 코드와 대본에 표시한다. |
| 21:20~21:50 | **시연 외 UI 차단** | 동작하지 않는 메뉴와 버튼을 숨기거나 비활성화한다. 클릭 가능한데 반응이 없는 요소를 0개로 만든다. |

### 월요일 종료 산출물

월요일 23:00 버전은 바로 시연할 수 있어야 한다. 기능 동결 이후 허용되는 변경은 **데이터 유실, 화면 진입 불가, 판정 오류, 업로드 실패, 집계 오류**와 같은 P0 결함 수정뿐이다.

| 11:15~11:35 | **복구 패키지 준비** | 초기화 명령, 마지막 성공 체크포인트, 테스트 증빙파일, URL 북마크, 역할별 시작 화면을 한 폴더에 정리한다. |
| 11:35~12:00 | **최종 동결** | 신규 배포를 중단하고 시연 직전 DB 상태를 백업한다. 대표 대상은 대본의 시작 상태로 되돌린다. |
| 12:00 이후 | **시연 대기 모드** | 신규 기능과 데이터 변경을 금지한다. 문제가 생기면 마지막 성공 체크포인트로만 복구한다. |

## 7. 시연 대본 목표 시간

| 구간 | 목표 시간 | 보여줄 내용 |
|---|---:|---|
| 대시보드 소개 | 1분 | 대상 수, 보완 건수, 현재 이행률 |
| 대상 조건과 법령 판정 | 2분 | 조건 입력, 적용 법령·조문·의무 도출 |
| 의무이행·증빙 등록 | 2분 | 조치일자 입력, 실제 파일 업로드 |
| 점검과 보완 요구 | 2분 | 역할 전환, `보완필요`, 점검내용 저장 |
| 보완과 재점검 | 2분 | 증빙 추가, `이행완료` 전환 |
| 총괄표와 대시보드 | 1분 | O/△/X/- 및 이행률 갱신 |
| **전체** | **10분** | 하나의 폐쇄형 업무 플로우 완주 |

## 8. 지연 시 기능 제거 순서

일정이 밀리면 아래 순서대로 제거한다. 데이터 저장·판정·점검·집계는 제거하지 않는다.

| 제거 순서 | 제거하거나 단순화할 기능 | 유지해야 할 대체 동작 |
|---:|---|---|
| 1 | 정식 로그인 화면 | 역할 스위처 또는 미리 준비된 데모 계정 사용 |
| 2 | PDF·이미지 인라인 미리보기 | 업로드와 다운로드만 유지 |
| 3 | 법령 신규 등록·수정 | 축소 법령 조회만 유지 |
| 4 | 검색 필터의 세부 옵션 | 법령명 단일 검색 유지 |
| 5 | 대시보드 부가 위젯 | 상태 건수와 이행률만 유지 |
| 6 | 애니메이션·반응형 모바일 | 시연용 데스크톱 해상도만 보장 |
| 7 | 비교 대상의 편집 기능 | 대표 대상 1개만 편집, 나머지는 시드 유지 |

## 9. 최종 완료 기준

화요일 완료는 화면 개수로 판단하지 않는다. 다음 조건을 모두 만족해야 완료다.

| 항목 | 합격 조건 |
|---|---|
| 법령 축소본 | 핵심 50~150개가 적재되고 원천 ID와 버전이 보존됨 |
| 판정 정확성 | 검수 규칙 8~12개만 실행되며 동일 입력은 항상 동일 결과를 냄 |
| 영속성 | 새로고침·재접속 후 조건, 이행일자, 증빙, 점검내용이 남아 있음 |
| 증빙 | 실제 파일 업로드와 다운로드가 가능함 |
| 보완 이력 | `보완필요 → 보완 제출 → 이행완료` 변경 이력이 남음 |
| 집계 | 상태 변경이 총괄표와 대시보드 이행률에 반영됨 |
| 시연 안정성 | 동일 대본을 초기화 후 2회 연속 성공함 |
| 복구 | 2분 이내에 초기 시연 상태로 복원할 수 있음 |
