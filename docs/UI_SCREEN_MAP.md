# 용인시 시연 UI 화면 구성

## 구성 원칙

화면명세 ZIP의 SCR-001~102를 동일 셸과 역할·상태 변형을 가진 **8개 대표 라우트**로 축약한다. 클라이언트 요청에 따라 `mockup.html`과 `화면설계서.md`의 적용범위 판정 UX를 첫 화면으로 승격했다. 용인시 마젠타·퍼플·청록 팔레트, 검정 GNB, 좌측 LNB, 고밀도 표를 공통으로 유지한다.

## 대표 화면

| ---: | --------------------- | ---------------------------------------------------------------- | --------------------------------------------------------------------------- |
|    1 | `/`, `/applicability` | Supabase의 ADOMS 승인 규칙으로 L1 법령→L2 대상→L3 의무 후보 판정 | 상시근로자·연면적·사실 기준일 변경, 3구간 결과, 근거 선택, 판정 스냅숏 저장 |
|    2 | `/dashboard`          | 역할별 대상·기한·알림·이행률 확인                                | 역할 전환, 후속 화면 이동, 시연 초기화                                      |

## 적용범위 판정 화면 계약

첫 화면은 다음 세 영역을 동시에 보인다.

1. **프로필·사실값:** 시설/업무 프로필, 상시근로자 수, 연면적, 시설물안전법 대상 여부와 값의 출처·가정 표시
2. **후보 결과:** 규칙상 조건 충족 후보, 프로필 연관·조건 확인 필요, 원천 검수 필요의 세 구간과 L1/L2/L3 건수
3. **근거 경로:** 프로필 사실→L1 rule→L2 대상→L3 의무, 법령·조문·원문 인용·`rule_id`·`unit_id`·`obl_id`

`seed_adoms.sql`의 `demo_approved=true` 규칙·연결만 조회하며 ‘적용조건후보’, ‘불명’, ‘이행기준’은 자동 판정에 사용하지 않는다. 첫 화면은 용인시청 관련 승인 규칙 4개를 선택 실행하고, 원격 조회 실패 시 동일 ID·근거의 내장 폴백으로만 동작한다. 저장 시 사실 발생·효력 기준일과 시스템 기록시각을 분리해 판정 스냅숏에 남긴다.

## 역할 변형

| 역할         | 화면 관점          | DB 쓰기 범위                   |
| ------------ | ------------------ | ------------------------------ |
| 담당자       | 지정 관리대상 중심 | 이행시기, 조치일자, 증빙, 비고 |
| 실·국 점검자 | 소관 대상 비교     | 점검 상태와 점검내용           |
| 경영책임자   | 전 기관 집계       | 조회 중심                      |

## 제외·비활성 범위

정식 로그인·회원가입, 전자결재, 관리자 전체 기능, 게시판, 전체 법령 자동판정과 통계 전건은 시연 범위에서 제외한다. 추진현황은 앱에서 제거하고 Excel/Google Sheets WBS로 관리한다.
