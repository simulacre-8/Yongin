# 용인시 시연 UI 화면 구성

## 구성 원칙

화면명세 ZIP의 SCR-001~102를 동일 셸과 역할·상태 변형을 가진 **8개 대표 라우트**로 축약한다. 클라이언트 요청에 따라 `mockup.html`과 `화면설계서.md`의 적용범위 판정 UX를 첫 화면으로 승격했다. 용인시 마젠타·퍼플·청록 팔레트, 검정 GNB, 좌측 LNB, 고밀도 표를 공통으로 유지한다.

## 대표 화면

| 순서 | 라우트 | 목적 | 핵심 상호작용 |
|---:|---|---|---|
| 1 | `/`, `/applicability` | 대상 프로필과 사실값으로 L1 법령→L2 대상→L3 의무 후보 판정 | 프로필·상시근로자·연면적·대상여부 변경, 3구간 결과, 근거 경로 선택 |
| 2 | `/dashboard` | 역할별 대상·기한·알림·이행률 확인 | 역할 전환, 후속 화면 이동, 시연 초기화 |
| 3 | `/targets` | 관리대상 검색·선택 및 기본정보 확인 | 시설 검색, 대상 선택 |
| 4 | `/laws` | 핵심 법령 축소본 검색 및 근거 확인 | 법령명·내용 검색, 구분 필터, Supabase 우선 조회 |
| 5 | `/obligations` | 검수된 대상별 의무와 이행시기 저장 | 월·반기 입력, 초기화 |
| 6 | `/evidence` | 조치일자·상태·증빙·비고 등록 | 상태 변경, 파일 선택, 행별 저장 |
| 7 | `/inspection` | 상위 조직의 증빙 확인과 상태·점검내용 판정 | 항목 펼침, 점검내용 편집 |
| 8 | `/summary` | O/△/X/- 행렬과 대상별 이행률 집계 | 앞 화면의 상태 변화 반영 |

## 적용범위 판정 화면 계약

첫 화면은 다음 세 영역을 동시에 보인다.

1. **프로필·사실값:** 시설/업무 프로필, 상시근로자 수, 연면적, 시설물안전법 대상 여부와 값의 출처·가정 표시
2. **후보 결과:** 규칙상 조건 충족 후보, 프로필 연관·조건 확인 필요, 원천 검수 필요의 세 구간과 L1/L2/L3 건수
3. **근거 경로:** 프로필 사실→L1 rule→L2 대상→L3 의무, 법령·조문·원문 인용·`rule_id`·`unit_id`·`obl_id`

축소셋의 검수 규칙만 실행하며 ‘참고’와 ‘이행기준’은 판정식에 사용하지 않는다. 조건 충족도 최종 법적 적용 확정으로 표현하지 않는다. 기존 ADOMS Graph API가 연결되기 전에는 동일 계약의 내장 검수 규칙으로 안전하게 폴백한다.

## 역할 변형

| 역할 | 화면 관점 | DB 쓰기 범위 |
|---|---|---|
| 담당자 | 지정 관리대상 중심 | 이행시기, 조치일자, 증빙, 비고 |
| 실·국 점검자 | 소관 대상 비교 | 점검 상태와 점검내용 |
| 경영책임자 | 전 기관 집계 | 조회 중심 |

## 제외·비활성 범위

정식 로그인·회원가입, 전자결재, 관리자 전체 기능, 게시판, 전체 법령 자동판정과 통계 전건은 시연 범위에서 제외한다. 추진현황은 앱에서 제거하고 Excel/Google Sheets WBS로 관리한다.
