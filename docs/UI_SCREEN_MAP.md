# 용인시 시연 UI 화면 구성

## 구성 원칙

화면명세 ZIP의 SCR-001~102는 102개의 독립 기능이 아니라 동일 셸과 표가 역할·대상·상태별로 반복되는 구조다. 화요일 시연에서는 **7개 대표 라우트와 상태 변형**으로 재구성한다. 연녹색 경영 배너, 검정 GNB, 연녹색 LNB, 회색 검색 패널, 계층형 표, O/△/X/- 상태색은 유지하되 이미지 자체를 사용하지 않고 React와 CSS로 다시 만든다.

## 대표 화면

| 순서 | 라우트 | 명세 대응 | 목적 | 현재 상호작용 |
|---:|---|---|---|---|
| 1 | `/` | SCR-006~009 | 역할별 대상·기한·알림·이행률 확인 | 역할 전환, 대상·의무 화면 이동, 시연 초기화 |
| 2 | `/targets` | SCR-027, 034 | 관리대상 검색·선택 및 기본정보 확인 | 시설 검색, 대상 선택, 다음 화면 이동 |
| 3 | `/laws` | SCR-024~025 | 핵심 법령 축소본 검색 및 근거 확인 | 법령명·내용 검색, 구분 필터, 상세 선택, Supabase `ref_law` 우선 조회 |
| 4 | `/obligations` | SCR-035 | 대상별 도출 의무와 이행시기 저장 | 월·반기 입력, 초기화, 로컬 영속화 |
| 5 | `/evidence` | SCR-086~087 | 조치일자·상태·증빙·비고 등록 | 상태 변경, 파일 선택, 행별 저장 |
| 6 | `/inspection` | SCR-088~089 | 상위 조직이 증빙을 확인하고 상태·점검내용 판정 | 항목 아코디언, 상태·점검내용 편집 |
| 7 | `/summary` | SCR-090 | O/△/X/- 행렬과 대상별 이행률 집계 | 앞 화면의 상태 변경 즉시 반영 |

## 역할 변형

동일 화면을 복제하지 않고 헤더의 역할 스위처로 컨텍스트를 변경한다.

| 역할 | 화면 관점 | 실제 DB 적용 시 쓰기 범위 |
|---|---|---|
| 담당자 | 지정 관리대상 중심 | 이행시기, 조치일자, 증빙, 비고 |
| 실·국 점검자 | 소관 대상 비교 | 점검 상태와 점검내용 |
| 경영책임자 | 전 기관 집계 | 조회 전용 |

## 제외·비활성 범위

정식 로그인·회원가입, 전자결재, 엑셀 산출, 관리자 전체 기능, 게시판, 통계 전체, 법령 신규등록은 이번 시연 범위에서 제외한다. 화면에 남아 있는 `결재하기`, `엑셀 다운로드`는 범위 제외 안내 토스트만 표시한다. 로그아웃은 비활성화했다.

## 상태 공유

현재 UI 골격은 `DemoContext`와 `localStorage`로 역할·대상·이행시기·증빙 메타데이터·점검 결과를 공유한다. Supabase 마이그레이션 적용 후 동일 인터페이스를 `target`, `target_obligation`, `compliance_record`, `evidence`, `inspection_result` 쿼리로 교체한다. 법령 화면은 이미 `ref_law`가 존재할 때 Supabase를 우선 조회하고, 테이블이 없으면 시연 축소본으로 안전하게 폴백한다.
