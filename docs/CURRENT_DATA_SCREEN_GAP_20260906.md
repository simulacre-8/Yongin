# 용인시 데모 현재 DB·화면 갭 보고

**기준일:** 2026-09-06
**검증 환경:** 호스팅형 Supabase + React + Netlify

## 결론

클라이언트가 제공한 **시설 150건, 용인시 전체 의무 3,688건, 시설–의무 매핑 2,906건**은 원격 Supabase에 구축됐다. 가상 경전철·도급 시나리오 3건을 별도 표시한 참조 계층은 대상 153건·매핑 2,929건이다.

이행시기, 실적·증빙, 이행점검, 총괄표는 더 이상 localStorage 전용이 아니다. `l2_result <> '제외'`인 대상 151건과 의무 2,891건을 업무 테이블로 투영했으며, 네 화면은 `target_ref + obl_id + 2026-H2`로 연결된다. 브라우저 저장과 원격 재조회도 확인했다.

현재 핵심 미연결 영역은 **이행현황 대시보드의 원격 집계**다. 적용판정·대상·의무·이행시기·실적·증빙·점검·총괄표는 시연 흐름에 필요한 원격 연결을 갖췄다.

## 화면별 동작 상태

| 화면               | 현재 보이는 내용                        | 원격 조회                         | 실제 저장                                |
| ------------------ | --------------------------------------- | --------------------------------- | ---------------------------------------- |
| 적용범위 판정      | 인원·면적, L1/L2/L3 후보, 근거          | ADOMS 법령·조문·규칙·의무         | `target_applicability`                   |
| 이행현황           | 대상·도래·초과·이행률·알림              | 일부 레거시 상태                  | localStorage 중심                        |
| 관리대상 현황      | FMS 150, 경전철, 도급·용역              | `v_managed_target_summary`        | 참조 읽기 전용                           |
| 관계 법령          | 법령 검색·필터                          | `ref_law`                         | 읽기 전용                                |
| 법 의무사항        | 시설별 적용 의무와 이행시기             | 매핑 + 전체 의무풀 + workflow     | `target_obligation.due_value`            |
| 의무이행(실적증빙) | 시설별 의무, 조치일·내용·상태·파일      | `v_facility_workflow`, `evidence` | `compliance_record`, Storage, `evidence` |
| 이행점검 및 조치   | 같은 의무의 이행일·증빙·비고, 점검 상태 | `v_facility_workflow`             | `inspection_scope/result`                |
| 점검 총괄표        | O·△·X·-와 이행률                        | `v_facility_workflow`             | 점검·이행 상태 집계                      |

총괄표는 점검결과를 우선하고, 점검이 없으면 이행상태를 사용한다. 둘 다 없으면 `해당없음(-)`으로 표시한다.

## 여전히 시연값인 영역

용인경전철은 FMS 시설물이 아니라 도시철도법상 공중교통수단이다. 클라이언트 세 CSV에는 경전철 운영주체와 실제 도급 계약원장이 없다. 따라서 용인경전철 1건, 도로 공사 1건, 경전철 시설관리 용역 1건은 `DEMO_VIRTUAL`로 유지한다. 실제 자산·계약 데이터를 받으면 이 세 레코드를 교체해야 한다.

## 시연 전 결정 필요

기본 시연 시설을 용인시청으로 둘지 고기상수도로 둘지는 클라이언트 확인이 필요하다. 현재 시설 업무 흐름은 실제 31개 의무와 저장 결과가 보이는 고기상수도를 기본 폴백으로 사용한다. 적용범위 판정의 프로필은 기존 용인시청 가정값을 유지한다.

도급·용역 상세를 화면 표시만 할지 실제 계약 테이블까지 만들지도 별도 결정이 필요하다. 화요일 핵심 시연에는 현재의 의무×시설 폐쇄루프가 우선이며, 신규 그래프 DB는 필요하지 않다.
